# 3D 뷰어 우클릭 이동 속도 보정

## 요청과 원인

- 우클릭 드래그로 화면을 이동할 때 모델이 지나치게 빠르게 움직이는 문제를 수정했다.
- 뷰어의 TrackballControls는 원근 카메라의 이동량을 카메라와 회전 중심 사이의 거리로 계산한다. 기존 고정 `panSpeed = 0.2`에는 카메라 시야각과 `zoom` 보정이 없었다.
- 축 정렬 프리셋은 원근 왜곡을 줄이기 위해 시야각을 0.75도로 좁히고 카메라를 멀리 배치한다. 이 상태에서 거리만 반영되어 일반 Iso 시야각 42도보다 화면상 이동 감도가 약 58.65배 커질 수 있었다.

## 변경 사항

| 파일 | 변경 |
| --- | --- |
| `frontend/src/features/viewer/viewer-controls.ts` | 공개 `update()`를 확장한 뷰어 전용 TrackballControls와 투영 보정 함수 추가 |
| `frontend/src/features/viewer/three-viewer-canvas.tsx` | 고정 panSpeed 대신 전용 컨트롤 사용 |
| `frontend/src/features/viewer/viewer-controls.test.ts` | 실제 TrackballControls에 우클릭 pointer 이벤트를 보내는 회귀 테스트 추가 |

이동 감도는 다음과 같이 보정한다.

```text
panSpeed = 0.16 × tan(effectiveFOV / 2) / tan(42° / 2)
```

- `effectiveFOV`는 카메라 시야각과 `zoom`을 함께 반영한다.
- 일반 Iso 기본 감도도 기존 0.2에서 0.16으로 20% 낮췄다.
- 매 컨트롤 업데이트 직전에 보정하므로 카메라 프리셋 변경, Fit, ROI 카메라 복원에도 적용된다.
- 기존 좌우/상하 정규화 방식은 유지했다. 마우스와 화면의 이동을 정확히 1:1로 맞추는 변경은 아니다.
- 좌클릭 회전, 휠 확대/축소, 우클릭 메뉴, 선택 계약 및 ROI 절단은 변경하지 않았다.
- 작은 Full View의 별도 pan 계산은 이미 시야각을 반영하므로 변경하지 않았다.
- CAD 좌표, 발광/수광 조건 및 광학 해석 결과에는 영향을 주지 않는다.

## 검증

- 전체 프런트엔드 테스트: **36개 파일, 236개 테스트 통과**.
- 신규 컨트롤 테스트: **7개 통과**. 시야각 42도/0.75도와 zoom 0.5/1/4 조건에서 동일한 드래그의 화면상 이동량을 비교했다. 프리셋 변경 직후 보정, 버튼 해제 후 정지, 드래그 없는 우클릭도 확인했다.
- 테스트는 실제 Three.js TrackballControls에 DOM pointer 이벤트를 전달하고 투영된 점의 이동량을 비교한다. WebGL 화면을 촬영해서 픽셀을 비교하는 테스트는 아니다.
- 프로덕션 빌드 및 TypeScript 검사 통과. lint 오류 0개, 기존 `result-window.tsx`의 `liveResult` 의존성 경고 1개 유지. 기존 번들 크기 경고도 유지했다.
- 실행 중인 `http://127.0.0.1:8788/`의 별도 테스트 탭에서 새 빌드를 로드하고 TV 우측 코너 STEP의 렌더링, XY 프리셋 전환 및 브라우저 오류 로그가 비어 있음을 확인했다.
- 브라우저 도구는 우클릭을 유지한 드래그를 지원하지 않아 실제 브라우저의 우클릭 드래그 감도는 위 자동화 테스트로 검증했다. 사용자의 기존 작업 탭은 새로고침하지 않았다.

## 적용 및 이력

- 적용 작업 폴더: `C:/Users/Administrator/Documents/TV leakage simulator main`.
