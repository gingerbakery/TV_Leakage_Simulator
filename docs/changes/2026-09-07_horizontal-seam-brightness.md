# 수평 이음매와 광원 밝기 비교

사용자가 오른쪽 측면의 데코·샤시 이음매가 세로가 아니라 가로라고 바로잡았다. 이전 side_seam 샘플은 세로 개발 기준으로 보존하고, 실제 요구 방향의 샘플을 side_seam_horizontal에 추가했다.

## 형상과 실제 해석

전면 +Z, 오른쪽 +X, 위쪽 +Y인 밀폐 합성 모델이다. 측면 x=120.4 mm에서 y=8~8+gap mm가 틈 폭이고 z=2~14 mm가 가로 길이 12 mm다. 전체 외피를 유지하고 ROI 절단이나 부품 제외를 사용하지 않는다. 내부 면광원과 광학 물성은 기존 Ray Tracing에 설정한다.

주 비교는 동일한 0.3 mm 틈에서 광원만 0/1/4/16 lm으로 바꾼다. 모든 조건은 CPU 500,000 rays, 같은 seed, 같은 형상과 배광이다. 생성 도구의 실제 검증 결과는 다음과 같다.

| 광원 | 수광 기하 경로 | 수광 광속(lm) |
| --- | ---: | ---: |
| 꺼짐, 0 lm | 104 | 0 |
| 기준, 1 lm | 104 | 8.10201e-6 |
| 4배, 4 lm | 104 | 3.24080e-5 |
| 16배, 16 lm | 104 | 1.29632e-4 |

광원 0 lm에서도 엔진은 에너지 0인 기하학적 경로를 기록한다. 그러므로 꺼짐의 기준은 수광 경로 수 0이 아니라 전달 에너지 0이다. 모든 저장 경로가 실제 수평 틈을 지나는지 검사했으며, 양의 광원 결과의 경로와 방향은 동일하고 각 광선·격자·방향별 에너지가 정확히 1:4:16으로 바뀐다.

## 화면 표현의 의미

빛샘 위치와 광량의 근거는 내부 광선 추적 결과다. 현재 자유 시점 화면은 그 출구 표본을 확인된 개구 영역에 재구성한다. 완전한 관측 카메라 경로 추적이나 실측 휘도 영상은 아니다. 특히 방향별 표시 함수는 경험적이며, 각 방향 구간의 입체각과 투영 면적을 적용한 물리적 radiance 보정은 후속 과제다.

동일한 외관, 시점, 표시 기준으로 결과를 비교한다. 화면 압축을 통과한 픽셀값이 1:4:16이어야 한다는 뜻은 아니다. 강한 빛의 화면 포화와 시인 문턱을 원본 광량 변화와 구분한다. 공통 기준을 바꾸거나 모델마다 자동 노출을 적용해 차이를 없애지 않는다.

빛을 좁은 면으로만 그리면 외관의 색 띠처럼 보일 수 있다. 추가하는 작은 화면상 번짐은 눈·카메라의 번짐을 흉내 내는 표시 시제품이며, 새로운 틈이나 주변 기구로 전달되는 광학 에너지를 해석한 결과가 아니다. 실제 틈의 형상과 깊이 가림은 유지한다.

## 결과 비교 흐름

완료된 결과의 CAD·광원·물성을 그대로 사용하며, 3D 화면 안의 비교 결과 선택으로 모델을 바꾼다. 표시를 위해 광학 조건을 다시 입력하거나 시점마다 Ray Tracing을 실행하지 않는다. 새 프리셋을 처음 불러온 경우에만 기존 Ray Tracing에서 결과를 만든다.

상세 재현 자료는 samples/side_seam_horizontal/README.md와 validation.json, 후처리 검증은 outputs/horizontal-seam-validation에 둔다. 기존 해석 엔진의 GPU/CUDA 경로는 이번 작업의 실행·검증 대상이 아니다.

## 빛샘 전용 화면 번짐과 선형 합성

빛샘 전용 표시 경로를 구현했다. 외관 영상과 빛샘 영상을 별도로 준비하고, 광선 결과에서 얻은 빛샘의 선형 에너지에만 작은 화면상 번짐을 적용한다. 표시장은 광량을 유지하는 7탭 가우시안 필터를 가로·세로로 나누어 적용하며, 원본 88%와 번짐 12%를 혼합한다. 반경 기준은 모든 모델에서 동일한 표준편차 1 CSS 픽셀이며, 모델의 갭 폭을 넓히거나 모델마다 효과 강도를 바꾸지 않는다. 프레임 가장자리는 반사 경계로 처리해 끝의 밝은 픽셀을 반복 복제하며 광량을 늘리지 않는다.

외관은 기존 보조 조명과 표시 압축을 유지한다. 빛샘은 선형 처리 후 한 번만 압축하고 외관과 선형 표시 공간에서 합성한 뒤, 마지막에 한 번만 화면 sRGB로 변환한다. 강한 광원에서 번짐이 더 눈에 띄더라도 화면 번짐으로 재분배한 에너지 자체가 증가한 것은 아니다. 깊이 판정에는 다른 기구 부품을 그대로 사용하므로 앞의 불투명 형상이 뒤쪽 틈을 가린다. 이 영상 효과는 눈·카메라의 작은 번짐을 가정한 시제품으로, 절대 휘도나 주변 기구의 실제 조명·반사 계산을 대신하지 않는다.

WebGL의 반정밀도 렌더 타깃을 사용할 수 없거나 선택적 표시 경로에서 오류가 나면 기존 직접 표시로 돌아간다. 재질의 색 기록 설정, 빛샘의 선형 출력 설정, 객체 표시 상태, 장면 배경 및 렌더러의 타깃·뷰포트·클리핑 영역·배경색은 정상 종료와 예외 모두에서 복원한다. 실제 작동 경로는 읽기 전용 canvas 속성 data-leakage-display-mode의 linear-psf/direct/inactive로 확인할 수 있다. 이는 화면 합성 경로의 표시이며 CUDA 해석 실행 증거가 아니다.

## 비교 시점과 처리 비용

이미 3D 빛샘 보기에 들어간 상태에서 비교 결과를 바꾸면 카메라 위치·관측 중심·위쪽 방향·화각·근거리/원거리 범위를 캡처한다. 새 Case 로딩으로 캔버스가 다시 생성되어도 기본 맞춤 이후 이 시점을 복원한다. 광원이 꺼져 출구 표본이 없는 결과에도 같은 시점이 적용된다. 휠 확대는 TrackballControls의 대기 중인 확대를 먼저 적용한 뒤 캡처해 마지막 한 단계가 빠지지 않도록 했다. 첫 진입의 기본 맞춤은 유지한다.

활성 상태의 표시 비용은 외관/빛샘을 위한 장면 그리기 2회와 화면 처리 3회다. 기존 프레임 간격 조절을 그대로 사용하고, 일반 Viewer로 나가면 추가 타깃과 재질을 해제한다. 타깃은 최대 786,432 픽셀, 한 변 최대 1,536으로 제한하며 화면 종횡비를 유지한다. 색 타깃 4개의 저장 공간은 최대 24 MiB이고 깊이·멀티샘플 버퍼는 별도다. 지원되는 멀티샘플 수는 최대 4로 제한했다. 큰 창에서는 타깃 해상도가 제한되지만 번짐의 CSS 픽셀 기준은 유지한다. CAD를 한 번 더 그리므로 대형 도면의 회전 성능은 별도 확인이 필요하며, Ray Tracing을 다시 실행하는 비용은 아니다.

## 코드 검증

영향받는 테스트 41개가 통과했다. 구성은 PSF 합성 8개, 표면 표시 2개, 결과 표본 추출 26개, 화면 연결 5개다. PSF 검증에는 중앙/프레임 끝 광원의 총 에너지 보존, 상수 영상 유지, 꺼짐에서 광량 0 유지, 표시 압축 전 1:4:16 관계, 타깃 크기 제한, 실제 기구 깊이 유지, 외관의 번짐 제외, 예외 시 상태 복원, 타깃 해제가 포함된다. TypeScript, 대상 파일 lint, git diff --check 및 production build가 통과했다. 마지막 휠 시점 수정 후 TypeScript와 production build도 다시 통과했다. jsdom의 UI 테스트는 실제 WebGL을 제공하지 않으므로 최종 셰이더 표시 확인은 브라우저 시연과 구분한다.
