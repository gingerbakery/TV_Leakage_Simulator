# 기존 검증의 경로 연결 근거 보강

새 메뉴·버튼·별도 실행 항목을 추가하지 않는다. 경로 검증의 기존 재생 결과, 동일 센서 광량 비교의 부족 항목·다음 행동, 기존 검증 JSON과 임시 AI export를 보강한다.

## 기록과 해석

- 대표 경로 재생의 `last_leg`: 마지막 진행 방향으로 CPU 교점·차폐·센서 조건을 검사한다. `included_in_flux=false`. 원래 광원에서 선택점까지 도달한 표본이 아니며 통과가 상류 확률을 보장하지 않는다.
- 비교의 `path_evidence[index].detected_paths`: 실제 실행된 event tape에서 회차당 최대 16개 검출 경로를 기록한다. 식별자는 광원 ID·광원 seed·primary index이며 reflection seed는 JS 정밀도 손실 없이 문자열로 보존한다. 기록 수·실제 hit 수·한도 초과·완료 상태를 포함한다. 구간 최근접 거리와 반사점 최근접 거리는 분리한다. 원래 비교 설정은 변경하지 않고 검증 복사본에서만 저장을 켠다.
- `policy_pair`: 기록된 기여가 큰 광선부터 회차당 최대 2개·전체 최대 16개를 CPU에서 재검사한다. 먼저 비교 조건에서 동일 primary index·reflection seed·표면 ID·좌표·광량 재현을 검증한다. 그 뒤 원래 종료 조건으로 실행하고 경로 prefix·종료 사유를 연결한다. 불일치·중지·오류는 미확정이며 통계 표본에 합산하지 않는다. 이 영향은 선택한 광선·검증 예산의 패킷에 한정되며 원래 일반 해석 전체나 실물의 단일 원인이 아니다.
- `reverse_diagnostics[index].stages`: 완료·커밋된 표본만 양수, 광원 연결 미확인, 연결 후 발광 0, 발광 양수이나 총 기여 0, 카메라 ROI 0으로 상호 배타 집계한다. 직접 hit와 가시 NEE 연결을 포함한다. 광원 연결 미확인은 기하학적 도달 불가능의 증명이 아니다. 종료 단계도 별도로 보존한다. 누락 카운터는 available=false이며 0으로 대체하지 않는다.
- CUDA resident의 기존 8개 출력 필드 의미를 유지하며 진단 3개 필드를 뒤에 붙인다. 첫 chunk의 기존 CPU 방정식 비교에 진단 정수 필드도 포함한다. 이 변경 자체나 CPU reference 통과는 실제 CUDA 실행 검증이 아니다.

기존 UI는 입력·완료·실행 증거를 확인한 후에만 새 근거를 활용한다. 표본 증가보다 확인된 광선 종료, 발광 조건, 실제 경로 연결 등의 다음 행동을 우선한다. 설명은 기존 (?) 도움말에 넣는다. 과거 결과에는 새 기록이 없을 수 있으며 기존 JSON에서 복원하지 않는다. 새 기록은 향후 경로 검증·광량 비교 실행 시 생성된다.

## 검증 범위

Source checkout, 기반 commit 8c0e72f 이후 작업 트리. 합성 CPU 장면에서 직접 도달, 2회 반사, 영역 이탈, 뒤쪽 교차, 뒷면, 수용각, ROI, 차폐, 표본 한도, 반사점/구간 거리 분리, 비영 primary index, 확률적 반사, 에너지·roulette 종료 연결, 재현 실패, 역추적 단계 집계 및 기존 추정량 보존을 검사한다. 프런트엔드는 누락·중복·합계 불일치·다른 광선 ID·미완료·이전 입력의 원인 오판을 검사한다.

실제 CUDA 장치 preflight/production 실행과 보안 PC CAD·실물 비교는 이번 로컬 검증에 포함하지 않는다. GPU 성공·실물 정확도는 주장하지 않는다. 서버 재시작·설치·배포는 하지 않는다.


로컬 확인 결과: 관련 CPU 테스트 89개 및 21개 subtest 통과, 프런트엔드 관련 55개 테스트 통과, production build 및 git diff --check 통과. 실제 GPU 실행 검증은 미수행이다. 기존 Vite chunk 크기 경고는 남아 있으며 이번 진단의 성공/실패 판정과는 별개다.
