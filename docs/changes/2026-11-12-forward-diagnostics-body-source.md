# 순방향 미검출 진단과 Body 광원 점검

## 변경

- Preview의 `순방향 진단 준비`는 선택 Point 기준 Receiver를 생성·갱신하고 진단 옵션을 켠다. Ray Tracing에서 실행한 뒤 결과 창의 `순방향 원인 진단`에서 센서별 도달 수, 최종 검출 수·lm, 제외 구간을 확인하고 JSON을 저장한다.
- 기존 자동 Receiver를 재사용해도 수용각 90°, 앞뒤 반전 꺼짐, 위치·크기·관찰 각도를 다시 적용한다. 사용자가 별도로 수정한 이전 센서 조건이 경로 검증용 센서와 달라지는 문제를 예방한다.
- 진단은 실제 진행 구간을 평행, 뒤쪽 교점, 면적 밖 투영, 앞선 형상 충돌, 다른 센서 선검출, 뒷면 입사, 수용각 제외, ROI 제외, 최종 검출로 분류한다. 앞선 형상에 막힌 투영을 센서 도달로 세지 않는다. 최종 검출 수·광량이 본 계산과 일치하는지도 확인한다.
- 전체 장면 이탈, 에너지 컷오프, 반사 한도, 확률적 종료도 표시한다. 장면 이탈은 특정 개구부 통과의 증거가 아니다. 구간 수·패킷 합은 반사 구간을 포함하므로 독립 Ray 수·고유 누출 광량으로 해석하지 않는다. 부분 결과를 구분하며, 반복 실행 누적은 횟수를 더하고 광량은 발사 수로 가중한다.
- 진단은 기본 꺼짐이다. 켜면 선택한 교차 계산 장치를 유지하고 CPU에서 구간을 관측하는 경로를 사용한다. GPU resident 전송·누적은 사용하지 않으므로 실행이 느려질 수 있으며, CUDA 실행이 실제 확인된 경우에도 혼합 실행으로 표시한다. 대표 경로를 검출·광량에 주입하지 않는다.

## Body 광원과 장시간 정체

사용자는 Body 선택 및 기존 Emitter 사용 두 방식에서 시야각 역추적이 50% 이상에서 5시간 넘게 진행되지 않아 직접 종료했다고 설명했다. 오류 없이 프로세스가 멈춰 보였다는 보고이며, native crash가 확인된 사례가 아니다. 해당 프로젝트·runtime fault log로 재현한 결과는 없다.

이전 Preview Body 선택은 Body의 최소 두께 축을 기준으로 **외접 사각 Plane**을 만들었다. 사각형이 실제 부품 윤곽 밖까지 발광할 수 있었다. 기본 방출 분포는 Lambertian이고 앞·뒤로 분리했다. 변경 후에는 선택 Body의 **실제 CAD 표면**을 면적 가중 샘플링하며 양면 Lambertian으로 방출한다. 임의의 외접 발광면을 추가하지 않는다. 여러 Body 사이의 총 1 lm과 Preview Ray 예산은 유지한다. 면 법선·형상 변환은 기존 Body Emitter 해석 경로를 따른다.

기존 Emitter 사용은 원래 설정된 Lambertian/균일 입체각/Aim·방출 방향·출력을 유지한다. 이전 프로젝트에 저장된 가상 Plane Emitter를 소급 변경하지 않으므로 새 Body 표면 방식은 Body를 선택하고 Preview를 다시 실행해야 적용된다. 부품을 등가 광원으로 지정하는 것이 투과·BTDF 광학 모델을 구현하거나 재질을 투과성으로 바꾼다는 뜻은 아니다.

확인한 반복 계산 비용을 다음과 같이 보완했다.

1. Resident 역추적이 매 구간마다 모든 CAD 광원 삼각형을 순회하던 부분을 첫 CAD 충돌 면의 광원 색인으로 대체했다.
2. 해석 제외 Body처럼 다수의 가상 발광 삼각형을 포함한 경우에는 순서를 보존하는 AABB 계층으로 후보를 줄인다. CPU 광량·경로 탐색과 resident 커널 방정식에 같은 보수적 후보 축소를 적용한다. 정확한 삼각형 교차·발광 방향·차폐 판정은 유지하며, 원래 순서와 공유 변 중복 제거를 보존한다.
3. Resident 광원 면적 표본 선택은 누적 면적 선형 탐색 대신 이진 탐색을 사용한다.
4. 가상 삼각형 수·깊이에 따라 한 번의 처리량을 제한한다. 샘플을 생략하지 않으며 배치 완료 경계에서 진행률·중지를 확인한다. 매우 큰 가상 광원에서는 배치 제한 자체의 전송 비용이 생길 수 있다.
5. Preview에 실제 서버 처리 단계와 표본 수를 표시하고, 60초 이상 수치가 바뀌지 않으면 `진행 갱신 없음` 경과 시간을 표시한다. 정지 확정 판정은 아니다. 서버 로그에는 광원 수·CAD 광원 면 수·가상 삼각형 수·계획 표본·최대 깊이·transport를 남긴다.

## 함께 정리한 미커밋 변경

Preview 표시 필터(대표 반사 한도·최소 nit·최대 밝기 대비 비율), 표시 상태의 프로젝트 저장·복원, 부드러운 Leak 마커와 클릭 반경, 전체 정밀 휘도 검색의 셀 반복 32/64 지원, 동일 센서 광량 비교의 다음 단계 안내와 표본 적용, 미검출 진단 표시를 포함한다. 표시 필터는 원본 광량·통계를 재계산하지 않는다. 상세 설명은 기본 닫힌 `(?)` 도움말에 둔다.

## 검증과 한계

- Frontend: 전체 100파일·840검사 통과. production build 통과(기존 큰 번들 경고 유지).
- Backend CPU: 순방향 진단·수광 광량·종료 조건·역추적·중지/재개·resident 방정식 oracle·광원 AABB 후보 검사 126검사 통과.
- 진단 on/off의 합성 다중 반사·컷오프·확률적 반사 광량과 검출 수, ROI 제외, 앞선 Receiver, 중지 부분 결과를 대조했다.
- 광원 후보 색인은 무작위 Ray의 전수 삼각형 검사와 비교해 실제 교차를 누락하지 않는지 검사했다. 공간적으로 떨어진 512삼각형에서는 검사 후보가 16개 미만이며 경계 교차를 유지했다. resident CPU 방정식 결과와 전수 순회 결과의 값·대표 경로도 대조했다. 이는 실제 장치 시간 측정이 아니다.
- 현재 전달 경로는 source checkout이다. 이번 검사에서는 NVIDIA 실기기·production GPU preflight·고객 도면의 5시간 정체 재현·성능 benchmark를 수행하지 않았다. 따라서 실제 GPU 실행 성공, 실제 도면 정체 해소, 물리적 빛샘 정확도가 검증됐다는 주장은 하지 않는다. 실기기 후속 검증은 저장소 GPU runbook에 따라 별도로 수행해야 한다.
- 사용자의 실행 중 서버·환경을 재시작하거나 driver/Toolkit을 설치하지 않았다.
