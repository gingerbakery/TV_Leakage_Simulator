# 2026-09-07 측면 직선 갭 시제품

사용자 요청은 TV 오른쪽 측면 하단에서 데코와 샤시가 일자로 만나는 0.1~0.5 mm 갭을 만들고, 기존 Ray Tracing Result에서 가느다란 선 형태의 빛샘을 돌려보는 시연이다.

## 적용

- `samples/side_seam`에 전면 +Z / 오른쪽 +X / 위쪽 +Y인 밀폐 합성 STEP와 설정 프리셋을 추가했다. 실제 사내 도면 대신 내부 120×80×16 mm, 벽 두께 0.4 mm, 측면 하단 길이 20 mm를 개발용 치수로 가정했다.
- 닫힘, 0.1, 0.3, 0.5 mm를 같은 1 lm 면광원, 임의의 불투명 무광 물성, CPU 조건으로 비교한다. 자세한 조건은 [샘플 설명](../../samples/side_seam/README.md)을 따른다.
- 평면 개구 검출은 기존 0.1 mm 격자로 충분하지 않은 좁은 틈에서 0.025 mm로 세분한다. 실제 CAD 삼각형과 선의 교차로 좁은 방향의 범위를 줄이며, 금속과 겹치는 셀 및 검사 영역 밖으로 열린 부분은 계속 제외한다. 모든 여섯 방향에 동일하게 적용하고 모델명·고정 측면 좌표로 분기하지 않는다.
- 결과 화면에 관측 방향 선택을 추가했다. 정면, 오른쪽·왼쪽 측면, 뒷면, 위·아래, 사선으로 이동한 뒤 기존 회전·확대·이동을 사용할 수 있다. 축 방향은 CAD 좌표 기준이다.
- 표시 방향 및 외관 변경은 완료 결과나 광원·광학 물성을 바꾸지 않는다. 새 광선 계산은 기존 Ray Tracing 실행에서만 한다.

## 검증과 한계

닫힘 기준과 세 갭의 모든 저장 수광 경로가 실제 측면 틈을 지나는지 검사한다. 연속광은 이 출구 표본과 실제 개구 영역으로 재구성하며 수광기 평면에 선을 그리는 방식이 아니다. 0.1 mm에서도 공통 표시 gain을 유지한다.

초기 100,000 rays의 0.1 mm 결과는 수광 표본이 7개뿐이었다. 시연용 최종 조건은 모든 모델을 같은 500,000 rays로 늘렸다. 이는 표본 보강용 기준 해석이며 렌더링을 열거나 회전할 때 반복하지 않는다. 표본 사이의 표현과 방향 분포는 시제품 추정이며, 실물 시인성이나 절대 nit·국부 밝기 수렴을 입증한 것은 아니다.

좁은 틈/6면/미세 금속 장벽을 포함한 mask 27개, 에너지장 14개, 렌더러 2개, 화면 연결 4개 테스트가 통과했다. TypeScript, lint, production build도 통과했다. 기존 L자 샘플의 면적과 에너지 보존·출력 절반 관계가 유지됨을 재확인했다. 이 작업은 CPU 합성 기준이며 CUDA 검증이 아니다.

샘플 BITSAM은 설정 전용이다. 새 CAD Case와 완료 결과의 일치를 유지하려면 한 번 Run을 실행해야 한다. 과거 결과를 새 Case에 재연결하는 저장·복원 문제는 이번 범위에 포함하지 않았다.

## 최종 500,000-ray CPU 기준

| 갭 | 수광 경로 / 연속광에 반영 | 실제·재구성 개구 면적 | 수광 광속(lm) |
| --- | ---: | ---: | ---: |
| 닫힘 | 0 / 0 | 0 mm² | 0 |
| 0.1 mm | 27 / 27 | 2 mm² | 7.33684e-6 |
| 0.3 mm | 219 / 219 | 6 mm² | 5.08655e-5 |
| 0.5 mm | 455 / 455 | 10 mm² | 9.09975e-5 |

701개 수광 경로 모두 의도한 측면 슬릿 통과를 확인했다. 평면장 재구성의 광량 보존 상대 오차는 최대 6.4e-16, 금속 위 재구성과 점 fallback은 0이다. 작은 합성 모델에서 표시 데이터 준비는 40~61 ms였다. 수광 응답 후 광속과 표시장의 입사 에너지는 서로 다른 값이므로 같은 양으로 해석하지 않는다.

100k에서 500k로 늘렸을 때 총 에너지 비는 0.1/0.3/0.5 mm 순서로 0.712/1.076/0.982였고, 총량으로 정규화한 공간 분포 L1 차이는 1.533/0.413/0.389였다. 모든 개구 셀에 표시 지지가 있더라도 특히 0.1 mm의 밝기 분포는 통계적으로 수렴했다고 볼 수 없다. 자세한 수치는 `outputs/side-seam-validation/surface-validation.json`에 기록했다.

시연 중 약한 선이 과도하게 어둡게 보이는 표시 오류도 확인했다. Three.js 기본 외관 재질과 달리 사용자 빛샘 셰이더에서 선형 색을 화면 sRGB로 변환하지 않았던 부분을 수정했다. 공통 gain·원본 에너지·문턱은 유지하며, 점 fallback에도 같은 변환을 적용한다. 직접 화면의 additive 합성은 여전히 정량적 선형 합성이 아니므로 실측 휘도를 의미하지 않는다. 카메라 맞춤과 방향 전환은 렌더링된 빛샘 영역을 중심으로 맞추도록 보완했다.

로컬 UI는 저장 경로 수를 1,000개로 제한한다. 이번 500k 시연에서 수광 경로 수는 이보다 작아 전체 수광 표본이 그대로 보존된다. 스크립트 검증의 저장 한도 5,000개와 구분한다.

## 최종 브라우저 시연 확인

로컬 8788 브라우저 한 곳에 세 CAD Case와 각 완료 결과를 유지하고, Result의 Case 선택으로 아래 실행 결과를 전환해 확인했다. 모두 Numba CPU 실행이며, 각 500,000 rays와 저장 경로 한도 1,000개를 사용했다. 이번 결과는 전체 수광 경로를 보존했다.

| Case | 갭 | 실행 ID | 수광 hit | 실행 시간 |
| --- | --- | --- | ---: | ---: |
| CASE 01 | 0.1 mm | rt3-8de13961c9eb | 27 | 20.694 s |
| CASE 02 | 0.3 mm | rt3-b20a0218e237 | 219 | 28.754 s |
| CASE 03 | 0.5 mm | rt3-be03a4854fcc | 455 | 15.884 s |

색 공간 변환 수정 후 세 모델 모두 오른쪽 측면(x_max)에서 연속광 표시를 직접 확인했다. 관측 방향 전환과 ‘빛샘 맞춤’으로 해당 측면을 확인했으며, 최종 화면은 0.5 mm 모델을 약간 비스듬히 회전하고 축소해 불투명 외관과 가느다란 선이 함께 보이는 상태로 남겼다. Case 선택을 바꿔도 위 세 완료 실행은 보존된다. 닫힘 기준의 빛샘 0 및 차폐 조건은 별도의 오프라인 검증에서 확인했다.

0.1 mm는 실제 화면에서도 매우 가늘고 약하며, 정확한 측면 방향에서는 일부 구간이 거의 보이지 않는다. 수광 표본 27개의 분포는 수렴하지 않았으므로 이 상태를 실제 제품의 밝기나 연속성 재현 완료로 판단하지 않는다. 화면 시연에서는 연속광의 위치, 얇은 틈의 범위, 회전에 따른 시인성을 확인한 것이다.

수정된 셰이더를 사용한 브라우저 오류 기록은 빈 목록이었다. 마지막 변경 후 화면 연결 4개와 렌더러 2개 테스트를 다시 실행해 총 6개가 통과했고, git diff --check도 통과했다. 화면 연결 테스트의 jsdom 환경에는 WebGL이 없어 관련 경고가 발생하므로, 실제 셰이더 표시 확인은 위 브라우저 시연 결과로 별도 구분한다.
