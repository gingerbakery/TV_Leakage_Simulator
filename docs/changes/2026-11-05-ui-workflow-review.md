# UI 작업성 점검 및 수정

2026-11-05. 기준 HEAD: `5cdf3a1` 및 앞선 미커밋 Block UI/화면 평면 생성 변경. 커밋·푸시하지 않은 추가 점검 기록이다.

점검 범위는 Block 그룹/개별 형상, Preview 실행·결과 목록, Viewer 입력·단축키, Workflow 탭 전환, ROI 좌표/목록, 부품 표시·Traceability, 정밀해석 Block 적용 상태다. 소스와 컴포넌트 DOM 검사를 기반으로 했다. 사용자 도면을 실제 앱에서 마우스로 조작한 사용성 실험이나 전체 UI의 시각 QA 완료를 뜻하지 않는다.

## 확인한 문제와 반영

| 문제 | 반영한 동작 |
|---|---|
| 목록 접기의 +/−와 형상 추가의 + 혼동 | 앞선 변경을 유지: 목록은 꺾쇠, 추가는 ‘형상 추가’, 작업 중 ‘추가 완료’. 전체 및 그룹 목록 접기 지원 |
| 개별 Block을 선택하는 목록과 치수를 편집하는 목록 중복 | 각 행에서 개별 ‘치수’를 열도록 통합. 그룹 전체 변경은 ‘그룹 치수’로 분리 |
| 숫자를 지우다 포커스를 옮기면 0으로 변경; 입력 중 매 글자마다 형상 변경 | Block 개별 숫자와 새 영역 깊이에 지연 확정 적용. Enter/포커스 이동 시 반영, 빈 입력·Esc는 기존 값 유지. 폭·높이·깊이는 최소 0.01 mm. 공용 NumberInput의 기본 동작은 유지하며 이 옵션을 Block에서만 사용 |
| 숨긴 그룹/전체 숨김 상태에서 추가하면 새 형상도 보이지 않음 | 추가 시작 시 전체/해당 그룹 표시를 켬. 해석 적용 OFF는 자동으로 ON으로 바꾸지 않음 |
| 표시와 해석 적용 혼동, 개별 OFF/Hide 상태 관리 곤란 | 그룹과 개별 ‘적용’ 체크, 개별 눈 버튼을 분리. 그룹 적용 OFF 상태는 경고로 표시 |
| Viewer에서 개별 형상을 선택해도 긴 그룹 맨 위로만 이동 | 그룹 펼침 후 실제 선택된 행으로 스크롤 |
| 구형 단일 Block은 ‘1개’로 표시되지만 하위 목록이 비어 있음 | 단일 항목도 선택·개별 치수 편집 지원. 가짜 하위 형상을 추가하지 않음 |
| 생성 모드를 끝내려면 패널 버튼을 다시 찾아야 함 | Esc로 현재 드래그/생성 모드 종료. 이미 만든 형상 유지, 빈 초안 정리. 입력 칸과 열린 대화창의 Esc는 가로채지 않음 |
| 다른 작업 탭으로 이동해도 Block 생성 모드가 남을 수 있음 | 해당 편집기를 떠날 때 자신이 시작한 모드만 종료. 다른 Case에서 시작한 생성은 건드리지 않도록 소유 Case/그룹 검사 |
| 수백 개 각도에서 밝은 관찰 방향을 찾기 어려움 | 휘도 결과를 기본 ‘휘도 높은 순’으로 표시하고 ‘각도순’ 선택 제공. 정렬을 바꿔도 선택 각도 유지 |
| -XY 뷰에서 경사진 CAD 면을 따라 Block이 기울어짐 | 앞선 변경 유지: CAD hit는 깊이만 사용하고 생성 평면/축은 카메라 화면 기준. 기존 형상은 그대로 유지 |

설명은 기존 `(?)` 도움말 안에 두고, 기본 화면에는 조작 이름·값·단위·선택/적용/작업 상태만 추가했다. 기본 화면에 새로운 사용법 문단을 넣지 않았다.

## 추가 개선 권장

| 우선순위 | 항목 | 판단 |
|---|---|---|
| P1 | Block 그룹 삭제/ROI 전체 삭제 되돌리기 | 즉시 삭제 후 복구 UI가 없다. 삭제 전마다 확인창을 띄우기보다 Case별 마지막 삭제 복구가 작업 흐름에 적합하다. 복구 범위·선택·해석 결과 무효화까지 설계해 별도 적용 필요 |
| P1 | 그룹 전체 형상 변경의 영향 표시 | 현재 사각→홀 형상 변경은 그룹 전체에 적용된다. 일괄 변환 전에 대상 개수와 되돌리기 제공이 필요하며 이번에는 변환 의미를 바꾸지 않음 |
| P2 | 대량 Block 목록 검색/필터 | 현재 접기·개별 행 스크롤은 개선했으나 이름/번호 검색과 적용 OFF만 보기는 없음. 수백 개 형상 작업에 유용 |
| P2 | 공용 숫자 입력 확정 정책 | 다른 화면은 기존 즉시 반영·빈 값 0 동작을 유지한다. 광원/ROI/재질 등 화면별 빈 값 의미와 실시간 미리보기 필요성을 정한 뒤 확장할 것 |
| P2 | 용어와 편집 단위 통일 | 그룹/영역/Block, 표시/적용/Traceability, 영어/한국어가 섞여 있다. 전체 명칭을 한 번에 바꾸기보다 각 화면의 실제 영향 단위와 저장 호환을 유지하며 정리 필요 |

부품 트리는 이미 표시와 Traceability를 별도 제어하며, 정밀해석에는 Blocker OFF 경고와 켜기 버튼이 있다. 이 동작은 유지했다. 해석 설정 변경·삭제 복구 정책과 광학 계산 의미를 이번 UI 점검으로 임의 변경하지 않았다.

## 검증

- 숫자 편집 확정·빈 입력·Esc, 개별/그룹 적용, 표시 재활성화, 구형 단일 Block, 패널 이탈과 Case 경계, 시야각 정렬의 회귀 검사를 추가했다.
- 관련 컴포넌트/상태/Viewer/Workflow/프로젝트 검사 10개 파일 132건 통과. NumberInput 기존 기본 동작 검사도 포함한다.
- TypeScript 및 production build 통과. 기존 500 kB 초과 bundle 안내는 남아 있다.
- 앞선 Block 생성 기하 검사에서 -XY의 경사진 면, 카메라 회전/roll, 역방향 드래그를 확인했다. 광학 성능·GPU 검증은 이 점검 범위가 아니다.

ROI 좌표 편집 UI 검사도 별도로 3건 통과했다. 최종 ‘그룹 치수’ 접근성 이름 정리 후 Block 편집 검사 13건과 production build를 재실행해 통과했다.
