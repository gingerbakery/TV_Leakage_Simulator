# Result 연결형 3D 빛샘 보기 — 1차 기반

## 구현한 범위

- Ray Tracing 실행 직전 CAD Case, 전체 mesh signature, transform, 광원, 수광기, 광학 profile·assignment, 제외 부품, ROI, 해석 설정을 결과의 `source_context`로 고정한다.
- 백그라운드 job이 완료될 때 실행 당시 snapshot을 결과에 연결한다. Case 전환이나 패널 unmount 뒤에도 launch context를 잃지 않는다.
- 자동 수렴을 사용하는 여러 Ray 구간도 각 실행 snapshot을 순서대로 보존하고 최종 Result에 중복 없이 병합한다.
- BITSAM은 새 context를 보존·검증하며 context가 없는 기존 파일도 계속 읽는다.
- Result 제목줄에서 선택한 Case의 `3D 빛샘 보기`를 바로 연다. 별도 광원·물성·카메라 해석 조건은 받지 않는다.
- 실행 당시 transform을 적용한 전체 형상의 외곽 경계와 Receiver 도달 저장 경로의 마지막 선분을 교차시켜 개발용 출구 표본을 만든다.
- 검정 배경, 형상 확인용 저조도 외관, 깊이 가림, ray 진행 방향과 카메라 방향의 정렬에 따른 밝기 변화, 자유 회전·줌·팬, Fit, Result 복귀를 연결했다.
- 개별 ray가 아니라 공간·방향 bin에서 에너지를 합한 뒤 공통 선형 표시 계수를 적용한다. 결과별 자동 밝기 정규화는 하지 않는다.
- 각 출구 표본에 slab 교차로 얻은 외곽 면을 저장한다. AABB 모서리·꼭짓점처럼 여러 면이 겹친 표본은 연속화하지 않고 점 표본으로 남긴다.
- Receiver별 hit 수, 저장된 Receiver 종단 경로 수, 유효 외곽 교차 수가 모두 맞을 때만 연속 표현을 허용한다. 저장 상한으로 경로가 잘린 결과는 자동으로 점 표본 표시로 돌아간다.
- 같은 외곽 면에서 1.2 mm 이내이고 진행 방향이 유사한 표본만 공간 해시로 연결한다. Relative-neighborhood pruning으로 L자 모서리의 대각선 지름길과 불필요한 긴 연결을 제거한다.
- 연결된 표본 군집은 world-space 광번짐과 검증된 짧은 연결 리본으로 표시한다. 공통 상대 표시 하한과 압축을 적용해 극미광 점 잡음을 줄이되 원본 Result는 바꾸지 않는다.

## 잘못된 판정을 막는 조건

- 실행 당시 Case·mesh가 일치하지 않으면 표시하지 않는다.
- ROI 또는 해석 제외 부품이 포함된 결과는 현재 외곽 경계 시제품에서 표시하지 않는다.
- Receiver hit가 있는데 저장된 Receiver 경로가 없거나 외곽 출구 표본으로 만들 수 없으면 검은 화면을 `빛샘 없음`으로 보여주지 않고 지원 중지 사유를 표시한다.
- 실행 후 형상 설정을 바꿔 Case의 최신 결과가 무효화되면 열려 있던 3D 빛샘 보기도 즉시 종료한다.
- 반복 진입 때 점·연속광 geometry와 shader material을 해제해 WebGL 자원이 누적되지 않게 했다.
- 3D 빛샘 보기에서는 기존 Section 조작 UI와 절단·cap 형상을 함께 숨겨 결과 화면에 분석용 overlay가 섞이지 않게 했다.
- 외곽 경계 계산은 face별 임시 객체를 보관하지 않는 2-pass 순회로 구성해 대형 CAD에서 불필요한 메모리 증가를 피했다.

## 현재 한계

- 외곽 AABB 교점은 물리적인 gap surface 검출이 아니다. 합성 코너의 첫 연결과 방향·가림을 확인하는 임시 방법이다.
- 저장된 Receiver 우선 경로만 사용하므로 전체 광량·실제 연속 발광 면적·모든 관측 방향 coverage를 뜻하지 않는다.
- 연속광 폭, 상대 표시 하한과 밝기 변환은 실험용 공통값이다. nit, 실제 보이는 gap 폭, 육안 검출 한계는 보정하지 않았다.
- 외관 조명은 CAD 형상을 알아보기 위한 약한 보조 조명이며 실물 암실 조명 해석값이 아니다.
- 기존 결과에 `source_context`가 없으면 정확한 Case·형상을 보장할 수 없어 새 3D 보기를 열지 않는다.

## 검증

- Result에서 선택한 다른 Case를 열 때 해당 Case가 실제 활성화되고 Result 창이 닫히는 통합 테스트를 추가했다.
- 닫힌 0-hit 결과, 변환 형상 교점, ROI·제외 부품 차단, mesh 불일치, 저장 경로 부족, 잘못된 path와 0 energy를 단위 테스트로 확인했다.
- 브라우저 합성 장면에서 Result 진입, 검정 배경과 저조도 외관, 방향이 맞을 때의 점 표시, 카메라 회전 후 방향 표시 소멸, Result 복귀를 시각 점검했다.
- `gap_0p5`의 실제 저장 Scene·Request·Result(20,000 rays, 118 receiver hits, 120 stored paths)를 제품 ViewerWorkspace에 연결해 시연했다. L자 코너 출구 표본이 관측 방향에서 밝아지고 카메라를 비틀면 약해지는 것을 확인했다.
- 같은 `gap_0p5` 결과에서 118 hit, 118 저장 Receiver 경로, 118 유효 교차가 일치함을 확인했다. 118개 표본 중 같은 면·근거리·유사 방향 조건을 만족하는 군집만 짧게 연결해 정면에서는 얇은 L자 광대로 보이고, 큰 사선에서는 방향 감쇠로 거의 사라지는 것을 다시 시각 점검했다.
- 검정 외관이 배경에 완전히 묻히지 않도록 표시용 보조 조명을 높이고, 합성 샘플이 식별되는 공통 선형 밝기 계수로 조정했다. 두 값 모두 물리 조도나 nit 보정값은 아니다.
- 전체 frontend 36개 test file의 234개 test, TypeScript 검사, lint, production build를 통과했다.
