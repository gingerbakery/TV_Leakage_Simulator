# Preview 저장 결과의 불필요한 재실행 판정 수정

2026-11-05 · source `db25ced` 기반 미커밋 변경.

기존 Preview는 설정 객체를 `JSON.stringify`한 문자열을 그대로 비교했다. 저장/복원 및 정규화 후 설정 값은 같지만 객체 속성의 삽입 순서만 달라져도 다른 입력으로 판단해 결과를 지우고 `Preview 재실행 필요`를 표시했다. 전체 정밀 검색에서는 전체 Ray Trace config도 비교 대상이어서 이 문제를 재현할 수 있었다.

새 입력 식별자는 객체 키를 재귀적으로 정렬해 만든다. 저장된 이전 식별자도 값 기준으로 비교하고 scene token 재연결 시 같은 정규화 규칙을 적용한다. Shell의 활성 Case 동기화도 속성 순서만 달라졌다는 이유로 Preview 상태를 다시 복원하지 않는다. 광원·변환 등의 배열 순서는 그대로 유지한다. 실제 값, 도면 token, 배열 실행 순서가 바뀌거나 식별자가 잘못된 경우 동등하다고 보지 않는다. 결과 수신/저장 복원/이어 실행/설정 변경 판단이 같은 비교 함수를 사용한다.

회귀 검사에서 정밀 Preview를 완료한 뒤 결과를 저장·복원하고 config/observer 키 순서만 바꾸면 기존 코드에서는 결과가 사라졌다. 수정 후 결과가 유지되고, 이어 검사 간격을 실제로 바꾸면 결과가 정상적으로 무효화된다. 이 수정은 이미 지워져 저장되지 않은 결과를 복구하지 않는다.
