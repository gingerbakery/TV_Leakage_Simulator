# 실물 양성·순방향 0 결과의 검증 연결

사용자가 설명한 불일치는 실물에서 보이는 지점이 순방향 최종 보고에서 0이라는 것이다. 아래 기능은 원인을 좁히기 위한 계산 내부 증거이며, 실물 도면의 불일치를 해결했다고 증명한 결과는 아니다.

## 1. 광량 비교의 상세 진단

동일 센서 광량 비교는 모든 순방향 회차에 `receiver_diagnostics=True`를 적용한다. 회차별 센서 도달·면적 밖 투영·앞선 형상·수용각·ROI 제외·최종 검출과 종료 집계를 `forward_diagnostics`에 보존한다. 중지나 실행 증거 부족으로 반환해도 이미 완료한 순방향 진단은 남는다. 별도로 실행하는 기존 종료 조건의 진단도 저장한다.

화면의 `순방향 상세 진단 · N회`, `기존 종료 조건 상세 진단`을 펼쳐 확인하고 각 진단 JSON을 저장할 수 있다. 비교 JSON에는 재생·진단·원본 요청 스냅샷·입력 해시가 함께 포함된다. 진단 구간 광량을 회차 추정 광량에 더하지 않는다.

GPU를 선택한 진단 실행은 CPU에서 전송·광학·구간 집계를 수행하고 CAD 교차는 선택한 CUDA provider에 요청한다. 진단 모드에서는 작은 wave의 정상 CPU hybrid 임계값을 끄므로, 작은 비교 표본도 CUDA 교차를 실제 시도한다. 가용성이나 실행 실패를 성공 처리하지 않으며 기존 production preflight·CUDA 성공 횟수 판정은 유지한다. 실행 증거가 있더라도 host 평가가 포함된 혼합 실행이다. 일반 GPU resident 경로보다 느릴 수 있다.

## 2. 대표 경로의 실제 순방향 재생

`경로 검증`은 기존 대표 경로의 기하·광학 조건 검사 후, 별도로 격리된 CPU 1 Ray를 재생한다. 광량 비교도 같은 재생 결과를 포함한다.

- 저장된 발광점과 첫 방향만 고정한다. 발광면/Aim의 기존 epsilon 출발 오프셋을 적용한다.
- 광원 표면은 실제 현재 발광 삼각형과 방출 방향으로 찾는다. 많은 면의 검색은 4,096개 단위 벡터 검사로 제한한다.
- `run_direct_ray_trace`의 내부 진단용 primary 입력을 사용한다. 하나의 활성 광원·1 Ray·CPU·진단 설정에서만 허용한다. 이 입력은 API의 일반 해석 요청 필드가 아니다.
- 원래 광원의 총 광량과 Ray 수에 따른 명목 패킷을 사용하여 상대/절대 에너지 컷오프를 유지한다. 원래 최대 반사·재질·종료 방식은 바꾸지 않는다.
- 이후 방향·반사·차폐·Receiver 판정은 실제 순방향 추적기에 맡긴다. 확산·Gaussian·Mixed·BSDF 반사를 저장된 경로 방향으로 강제하지 않는다.
- seed는 원래 광원 seed, 없으면 config seed를 고정한다. 일반 무작위 추적에서 해당 경로가 표본화됐다는 의미는 아니다.
- 같은 위치·방향을 지지하는 광원이 여럿이면 원래 광원과 패킷을 임의 선택하지 않고 재생 미실행/중첩 광원 식별 불가로 표시한다.
- 저장 반사점과 실제 충돌점을 비교하여 첫 불일치 구간과 좌표, 일치점 수, 실제 이벤트·종료·센서 제외 정보를 반환한다. 에너지 컷오프, 최대 반사, 확률적 종료, 확률적 분기 변경을 구분한다.
- API의 `simulation_run_started=False`는 본 해석 worker/job을 시작하지 않았다는 기존 의미를 유지한다. 추가 필드 `diagnostic_forward_replay_started`와 `validation_scope`로 격리된 재생 실행을 명시한다.
- 재생의 검출·광량은 본 해석이나 순·역방향 광량 추정에 합산하지 않는다. CPU 재생 결과를 GPU 정확도나 실물 정확도 증명으로 해석하지 않는다.

재생 실행 오류는 `failed / replay_execution_failed`이며 0 검출과 구분한다. 광량 비교는 이 경우 `reference_replay_failed` 미확정으로 중단하고 표본 증가를 권하지 않는다. 경로가 없는 일반 센서의 비교는 기존대로 가능하며 재생은 미실행으로 표시한다.

## 3. 전체 입력 동일성

비교 시작 시 서버가 원본 요청의 깊은 복사와 SHA-256을 job에 보관한다. 완료·중지 보고서에도 포함한다. 화면은 서버 스냅샷과 현재 요청을 같은 JSON 정규화 규칙으로 비교한다. 센서 ID·크기만 같아도 위치·법선·flip·광원·재질·BSDF·ROI·변환·종료 조건·장면 token 등이 다르면 이전 결과로 표시한다. 표시용 프로젝트 이름만 제외한다.

물리 입력 SHA-256은 기존대로 서버가 준비한 형상·재질 배치·광학 조건을 식별한다. 브라우저는 서로 다른 숫자 직렬화 규칙으로 이를 다시 해싱하지 않는다. 스냅샷이 없는 예전 결과는 입력 동일성 미확인으로 취급하고 현재 조건의 권장 표본 설정을 제공하지 않는다.

## 검증 범위

정반사 대표 경로 재현, 명목 패킷/원래 컷오프 유지, 첫 충돌 불일치, 확률적 반사 비강제, 재생 실행 오류, 본 입력 불변, product job 미생성, 비교 진단 보존과 오류 시 미확정, 전체 입력 동일성 및 예전 결과 차단을 검사한다.

Frontend 전체 102파일·846검사, 관련 backend CPU 47검사, 타입 검사와 production build가 통과했다. Lint는 오류 없이 기존 hook 의존성 등의 경고를 유지한다. 큰 번들 경고도 유지된다.

실제 고객 도면·실물 관찰의 대응 검증과 NVIDIA 실기기 실행은 이 변경의 검사 범위에 포함하지 않는다. 실물에서 보이는 경로가 현재 광원·재질·투과 모델에 포함되는지도 별도 확인해야 한다. 비교 허용 차이·최소 유효 표본·0 검출 미확정 기준은 완화하지 않았다.
