## 반사 상한 진단

32,768 Ray 고정으로 진단 프로세스에서만 1,000→2,000→3,000→5,000회를 비교했다.
GPU 독립 4 seed 평균은 다음과 같다.

| 상한 | Receiver Flux(lm) | Raw Peak(lux) | 상한 종료 잔여 에너지 상계 / 입력 |
|---:|---:|---:|---:|
| 1,000 | 0.531638399 | 22,566.0065 | 5.596841% |
| 2,000 | 0.562730904 | 23,793.9520 | 0.297792% |
| 3,000 | 0.564373734 | 23,867.4972 | 0.016271% |
| 5,000 | 0.564466281 | 23,871.5028 | 0.000133% |

1,000회 상한에서 결과가 충분히 수렴하지 않은 사례다. Ray 수만 늘려서는 이 잘림 영향을
없앨 수 없다. 상계는 상수 반사율/동일 초기 가중치/MIS OFF의 이번 표본에서
`상한 종료 수 / 발사 수 × 0.999^상한`으로 계산한다. 실제 Receiver 누락량 또는 모집단
신뢰상한과 같은 뜻이 아니다. 제품의 지원 상한은 1,000회로 유지한다.

2,000/5,000회 경면 복도는 양 장치 모두 이론 광속 `0.999^반사수`, Receiver hit 64개,
surface hit `64×반사수`와 일치했다. 복잡 공동의 CPU 상한 대조는 별도 한 seed를 사용한다.

CPU 공동의 5,000회 결과는 Flux 0.565191300 lm, Peak 23,713.6057 lux였다.
추가 실행 총 57회(고표본 16, 상한 20, 첫 실행+warm 15, 이론 대조 4, batch 대조 2)를
완료했다. 장치 내 warm 대조 10건과 이전 날짜 GPU 재실행 8건, CPU batch 1,024→256 및
GPU batch 2,048→256 모두 엄격 허용오차 내 통과했다. 모든 실제 GPU 실행은 CUDA 성공
양수 및 resident/intersection fallback 0을 확인했고, 병행 진단이므로 시간을 정식 성능 비교로 쓰지 않는다.
57개 정상 격자의 지표 재계산과 transport 함수의 HEAD 대비 AST 동일성도 확인했다.

## 확정된 추가 코드 오류와 수정

최고 셀의 통계가 정상이어도 밝은 영역의 다른 셀에 제곱합 통계가 없으면 영역 오차가
과소평가될 수 있었다. 2개 셀 `[1, 0.5]`의 재현에서 기존 backend 오차는 약 1.856%,
누적 UI 오차는 약 1.312%로 표시됐다.

- 밝은 영역의 양수 광량 셀에 제곱합이 0/음수/비유한 값이면 영역 오차를 `null`로 둔다.
- UI의 기존 결측 오차 처리와 연결하여 자동 수렴 통과를 차단한다. 목표 100%에서도 결측은 통과하지 않는다.
- 광량 합계, raw Peak, 광선 방향/반사, GPU 커널은 변경하지 않는다.
- 정상 통계와 zero-hit의 기존 계약은 유지한다. 이전 Peak 셀 오차/변화율 보완과 함께 적용한다.
- backend 77개, frontend 전체 297개(41파일), 타입 검사 및 별도 빌드 통과.
- 실행 서버와 production dist를 교체하거나 재시작하지 않았다. 커밋/push도 하지 않았다.
