# 암실 빛샘 렌더링 프로토타입 계획

- 작성일: 2026-09-03
- 상태: Result 연결형 3D 보기와 합성 코너의 표본 기반 연속광 1차 구현 완료. 외관 프리셋·관측 보정·일반 도면 확장은 진행 전이다.
- 검토 근거: 현재 코드 정적 분석과 CIE/Radiance 공식 자료. 별도 합성 차폐 샘플의 CPU 광선 추적은 실행했으며, 관측 렌더러와 실물 정합 시험은 아직 수행하지 않았다.
- 선행 검토: [외관 렌더링과 자동 설계 검토](reports/2026-09-03_rendering-and-design-assistance-feasibility.md)
- 착수 순서와 첫 완료 기준: [Rendering Studio 착수 계획](rendering-studio-implementation-plan.md)

## 1. 이번 범위

사용자의 우선 목표는 완전 암실에서 빛샘이 얼마나 밝고 크게 보이는지 확인하고, 그 차이를 모델별로 비교하는 것이다.

확정한 방향:

1. 자동 설계는 V1이 완전히 개발 완료된 이후 후속 버전으로 미룬다. 현재 렌더링의 선행 작업으로 요구하지 않는다.
2. 최초 주변 환경은 거의 0 lux인 완전 암실이다. 첫 계산 모델은 외부 환경광 0으로 단순화한다.
3. 평가에서 무시할 아주 약한 빛은 외관 영상에서 표시하지 않도록 공통 기준을 마련한다.
4. 사용자가 제품 주위를 회전·확대·이동하며 볼 수 있어야 한다.
5. 외관 색과 마감을 소수의 프리셋으로 지정한다.
6. 모델별 관측 위치를 저장하고, 공통 표시 기준으로 밝기와 보이는 크기를 비교한다. 같은 위치·거리·각도를 모든 모델에 강제하지 않는다.
7. 완료된 Ray Tracing Result에서 3D 빛샘 보기로 이어진다. 별도 스튜디오 진입·모델 가져오기·광학 조건 재입력을 요구하지 않는다.
8. 사용자가 돌려보면 여러 각도의 빛샘이 자동 갱신되는 3D 관측이 첫 제품 목표다. 고정 이미지와 각도별 Render 버튼 중심의 초기 제안은 대체한다.
9. 1차는 절대 nit 일치보다 실제 틈의 위치·모양·기구 가림과 빛샘의 시각적 확인에 집중한다. 제품 외관은 사용자 지정 색·간단한 표면 마감을 표시 재질에 적용한다. 이 표시 설정은 기존 광학 해석 물성을 바꾸지 않는다.

사용자 후속 정정에 따른 현재 흐름은 `기존 조건 설정 → Ray Tracing 완료 → Result의 3D 빛샘 보기 → 회전·확대하며 관찰`이다. 광원·광학 물성·형상은 선택한 결과를 생성한 당시의 설정을 사용한다. 내부 모듈 분리는 가능하지만 새 해석 설정을 반복하는 사용자 흐름으로 만들지 않는다. ROI의 구체적인 처리는 이 결과 연계와 3D 관측 방식을 확정한 뒤 검토한다. 착수 내용은 [수정한 구현 계획](rendering-studio-implementation-plan.md)을 따른다.

사용자는 실제 사내 세트 CAD를 외부로 반출할 수 없다고 설명했다. 외부 개발은 코드로 만든 시험 형상으로 진행하고, 실제 제품 데이터의 적용·보정·검증은 사내에서 수행하는 흐름으로 계획한다.

외부 환경광 0은 제품 광원이 꺼졌다는 뜻이 아니다. 빛샘을 발생시키는 내부 광원은 동작하며, 필요 시 TV 화면의 검정 상태 휘도도 관측 조건에 기록한다. 화면·실내 반사 모델을 생략하는 초기 장면은 그 가정을 명시한다.

### 사용자가 제공한 사내 관측 조건

2026-09-03 추가 설명을 기준으로 다음을 기록한다. 측정 데이터 파일을 확인한 결과가 아닌 사용자가 제공한 현장 기준이다.

| 항목 | 제공된 조건 | 적용 |
| --- | --- | --- |
| 대상 | TV 코너의 LCD 셀과 기구 최외곽 데코 사이 틈 | 해당 틈의 관심점을 카메라 target과 회전 중심으로 지정 |
| 스크린에서 수직으로 떨어진 거리 | 5~20 cm, 즉 50~200 mm | 스크린 평면으로부터 관측점의 수직거리 |
| 대각 직선 관측 거리 | 약 20~40 cm, 즉 200~400 mm | 선택한 빛샘 관심점에서 관측점까지 거리로 해석하며 실제 기준점은 관측 설정에 기록 |
| 관측 각도 | 스크린 법선 기준 10~30° | 사용자 후속 답변으로 기준축 확정. 눈/카메라에서 코너 틈새를 바라보는 시선과 스크린 법선 축 사이의 예각 |
| 관측 수단 | 육안 및 비전 카메라에서 동일한 관측 배치 | 위치·방향 프리셋 공유. 육안 표시 문턱과 카메라 검출 조건이 같다는 뜻은 아님 |
| 관측되는 빛샘 밝기 | 최대 약 1~2 nit 수준 | 초기 비교 화면의 저휘도 범위를 잡는 참고값. 최소 표시 문턱이나 합격 한계값은 아님 |

현재 확정되지 않은 값은 최소 표시 휘도, 실제 검사에서 함께 쓰는 거리·각도 조합, 비전 카메라의 노출·게인·영상 처리 조건 등이다. 이 값들을 사용자 제공값인 것처럼 채우지 않는다.

### 관측 위치의 기하학 계약

선택한 코너 관심점이 스크린 평면 위에 있다고 놓고, 관심점과 관측점의 직선거리를 `r`, 스크린 평면에서의 수직거리를 `h`, 스크린 법선 축 기준 관측각을 `theta`라고 정의한다. 화면 전면 법선이 바깥으로 향한다면 카메라 위치 계산에는 관심점에서 카메라를 향하는 벡터를 사용하고, 카메라는 반대 방향으로 관심점을 바라본다.

- 사용자 확정 기준에 따라 `h = r × cos(theta)`를 사용한다.
- 평면 안의 이동거리는 `r × sin(theta)`이다. 관측각을 스크린 평면 기준으로 바꾸어 해석하지 않는다.
- 따라서 수직거리·직선거리·각도를 서로 독립적인 세 입력으로 강제하지 않는다. 두 값에서 나머지를 계산하고 제공된 범위와 맞는지 검사한다.
- 스크린 평면 안에서 어느 방향으로 코너를 보는지도 필요하다. 이 방위각은 카메라 조작으로 정하고 함께 저장하며, 현재 수치로 확정하지 않는다.
- 실제 관심점이 스크린 기준면에서 벗어나면 그 오프셋을 좌표 계산에 포함한다.

법선 10~30°, 직선거리 20~40 cm에서 계산되는 수직거리는 약 17.3~39.4 cm이다. 제공된 수직거리 5~20 cm와 동시에 만족하는 조합은 일부이며, 같은 기준점을 가정하면 직선거리 약 20~23.1 cm 부근으로 제한된다. 제공 범위는 현장 범위로 보존하고, 모든 조합이 한 관측점을 뜻한다고 강제하지 않는다. 예를 들어 수직거리 5 cm는 직선거리 20 cm 이상·법선 10~30°와 동시에 성립하지 않는다.

초기 시험 프리셋 제안은 직선거리 20 cm에서 법선 10°/20°/30°의 세 관측점이다. 수직거리는 각각 약 19.7/18.8/17.3 cm로 세 조건 범위에 들어간다. 중심 예시는 `직선거리 20 cm, 법선 기준 20°, 수직거리 약 18.8 cm`로 잡는다. 이는 합성 모델의 시작 예시이며 모든 TV에 적용할 고정 검사 위치가 아니다. 각 모델의 실제 검사 위치를 사용자가 정하고 저장한다.

## 2. 미광 표시 기준

최신 1차 범위에서는 아래 절대 휘도 문턱과 실측 보정을 선행 조건으로 두지 않는다. 상대 표시 스케일과 실험적 표시 문턱으로 외관 미리보기를 먼저 검증하며, 상대 가중치를 nit로 표기하지 않는다. 아래 내용은 방향별 휘도와 실측 기준을 갖춘 후 확장할 목표로 보존한다.

### 기준의 의미

암실이라는 조건만으로 보임과 안 보임을 가르는 휘도값 하나를 정할 수는 없다. 시각의 휘도 검출 문턱은 대상의 크기, 주변, 적응 상태와 관측 조건에 따라 달라진다. [CIE의 luminance threshold 정의](https://cie.co.at/eilv/720)

첫 프로토타입은 검증 가능한 **공통 최소 표시 휘도**를 사용한다. 이것은 조건을 정한 평가용 표시 기준이며, 보편적인 사람 눈의 검출 한계나 자동 합격 기준으로 설명하지 않는다. 정확한 수치는 현재 정하지 않는다. 기준 샘플이 없으면 조정 가능한 실험값으로 구현하고 보정 전 상태를 표시한다.

사용자가 제공한 최대 약 1~2 nit를 최소 표시값으로 적용하면 그보다 약하지만 실제로 보이는 빛샘을 숨길 수 있다. 초기 비교 눈금은 0~2 nit 부근을 중심으로 검토하되, 원본 값은 제한하지 않고 2 nit를 넘는 결과도 수치와 범위 초과 상태로 보존한다. 이는 계산 휘도의 표시 범위 제안이며 모니터 자체의 실제 출력 휘도를 0~2 nit로 보정했다는 뜻은 아니다.

### 제안 처리 흐름

`광학 계산 → 관측 방향별 선형 휘도 누적 → 표본 품질 확인 → 공통 표시 문턱 적용 → 고정 노출로 화면 변환`

- 문턱은 개별 ray의 에너지에 적용하지 않는다. 약한 광선들이 합쳐져 의미 있는 밝기가 될 수 있으므로, 관측 픽셀 또는 정의한 관측 영역의 누적값에 적용한다.
- 원본 휘도와 해석 데이터는 보존한다. 표시 문턱은 광학 계산의 에너지 종료 조건인 `min_energy`와 별개다.
- 문턱 아래는 외관 영상에서 숨긴다. 경계 근처에는 고정된 짧은 전이 구간을 둘 수 있지만, 모델마다 경계를 바꾸지 않는다.
- 밝기 비교에서 모델별 자동 노출과 최대 밝기 정규화를 사용하지 않는다. 같은 값은 같은 표시값으로 변환한다.
- 초기에는 임의의 bloom·발광 번짐을 사용하지 않는다. 번짐은 보이는 크기를 바꾸므로 추후 관측 모델과 실측으로 검증한 경우에 추가한다.
- 계산 중의 점상 잡음과 실제 작은 빛샘을 구분한다. 단순히 작은 점이나 몇 픽셀짜리 영역을 삭제하지 않는다. 표본이 부족하면 추가 계산과 품질 상태로 다룬다.
- 문턱 근처에서 결과가 불안정하거나 hit가 부족하면 판정 미확정으로 표시한다. 검은 영상만으로 빛샘 없음 또는 육안 비검출을 확정하지 않는다.

노출·디스플레이 변환과 원래 휘도값의 분리에는 [Radiance pcond의 문서](https://www.radiance-online.org/archived/radsite/radiance/man_html/pcond.1.html)를 참고한다. 이 도구의 자동 시각 보정을 그대로 채택한다는 뜻은 아니다.

### 보정 방법

대표 샘플에서 `명확하게 보이는 빛샘 / 경계 수준 / 평가에서 무시하는 미광`을 같은 조건으로 관찰한다. 관찰 거리·방향, 암순응 조건, TV 동작 상태를 기록한다. 가능하면 대응 위치의 휘도 측정값과 고정 촬영 조건의 사진을 확보한다.

사내 관찰 거리 범위와 최대 휘도 수준은 제공되었다. 최소 표시 문턱을 보정하려면 이보다 약한 경계 수준의 사례가 여전히 필요하다. 비전 카메라 사진과 비교할 때는 동일한 관측 배치 외에 노출·게인·후처리 설정도 기록한다.

초기 공통 문턱과 화면 변환을 이 자료에 맞춘 뒤, 별도 모델에서 순위와 보이는 범위가 유지되는지 확인한다. 조정한 값은 보정 프로필 버전으로 저장하고 모든 비교 모델에 공통으로 적용한다. 보정된 휘도 데이터가 없으면 추정 단위에 대한 임시 기준임을 표시한다.

거리와 빛샘의 각도상 크기를 반영한 시각 모델은 후속 단계다. 처음에는 각 모델의 관측 조건을 저장해 재현성을 확보하고, 모델 간 관측 조건 차이를 비교 결과에 함께 기록한다.

## 3. 밝기와 크기의 정의

첫 외관 미리보기의 위치·형태·가림 검증과 후속 정량 지표를 구분한다. 제한된 저장 경로로 만든 상대 표시를 절대 휘도나 검증된 가시 면적이라고 부르지 않는다.

### 밝기

- 선택한 빛샘 영역의 추정 휘도 분포, 대표 밝기, 최대값을 기록한다.
- 최대값은 표본 잡음에 민감하므로 고정된 영역의 평균이나 공간 평균 지표를 함께 표시한다.
- 미광 표시 문턱을 올렸을 때 밝기가 개선된 것처럼 보이지 않도록, 원본 영역 지표와 표시 문턱을 결과에 함께 기록한다.
- 초기 출력은 단색 휘도로 시작한다. 회색 계열의 외관 프리셋은 이 범위와 잘 맞는다.

### 크기

- **보이는 범위:** 같은 관측 조건에서 공통 표시 문턱 이상인 영상 영역의 폭·길이·크기.
- **형상 위 크기:** 표면 또는 명시한 기준면에 대응할 수 있을 때만 mm·mm²로 환산한다.
- 틈을 통해 보이는 광원이나 깊이가 섞인 영상은 한 면의 실제 면적과 같지 않을 수 있다. 이 경우 각도상 범위 또는 기준면 투영 크기로 표시한다.
- 화면 확대 비율과 제품을 관측하는 실제 거리를 구분한다. 픽셀 수만을 제품의 mm 크기로 보고하지 않는다.
- 작은 밝은 점, 얇은 선, 넓고 어두운 얼룩을 각각 확인할 수 있게 하며 최소 픽셀 면적만으로 제거하지 않는다.

현재 `result-window.tsx:207`과 `:274`의 광영역은 각 Case 또는 Receiver의 최대 추정 휘도 대비 1/5/10% 문턱을 사용한다. 새 암실 비교에서는 별도로 공통 표시 문턱을 적용해야 한다. 기존 Receiver 면적을 제품에서 보이는 면적으로 그대로 대체하지 않는다.

## 4. 카메라와 제품 외관

### 카메라

사용자가 말한 피벗은 **카메라 회전 중심**으로 정의한다. 제품 전체 또는 선택한 빛샘 부위를 중심으로 돌려 본다. 제품 구조나 광원 위치를 실제로 회전시키는 Transform과는 구분한다.

- 기존 회전·확대·이동 조작 재사용.
- 전체 보기, 정면/측면, 선택 부위 중심, 기준 시점으로 복귀.
- 관측 위치·방향·거리·화각·화면 비율·회전 중심을 저장.
- 모델마다 하나 이상의 관측 위치를 저장하고 활성 관측 위치를 복원. 모델 비교 시 관측 조건 동기화는 선택 기능으로 제공.
- 카메라를 돌리면 해당 완료 결과와 관측 데이터를 바탕으로 그 방향의 가림과 반사광이 자동 갱신된다. 기존 영상 한 장을 회전시켜 새 관측 결과로 사용하지 않으며, 시점마다 Render 클릭을 요구하지 않는다. 필요한 데이터 재사용·보완 계산의 방식은 기술 검증으로 결정한다.
- 조작 중에는 저품질 미리보기, 멈춘 뒤에는 누적 계산하는 방식을 우선 검토한다. 즉시 고품질 갱신이 가능한지는 대표 모델에서 측정해야 한다.

현재 `three-viewer-canvas.tsx:1916`에 TrackballControls가 있다. 다만 `:601`의 외부 전달 카메라 프레임은 target과 방향축 중심이므로 새 관측 계약에는 거리와 화각 등을 추가해야 한다. CAD용 축 정렬 뷰는 작은 FOV를 사용하므로 실제 관측 비교의 거리·화각 기준으로 그대로 사용하지 않는다.

### 외관 프리셋

초기 제안은 검정·진회색·밝은 회색/실버·흰색의 소수 색상과 무광·반광·유광 마감이다. 정확한 구성은 대표 제품과 광학 지원 범위에 맞춰 줄일 수 있다.

현재 화면 표시 색은 광학 Material Assignment와 독립적이다(`viewer-display.ts:65`). 새 렌더링에서는 표시 색, 외부 표면의 반사 특성, 기존 내부 광학 재질의 연결 규칙을 정해야 한다.

첫 물리 검증에는 무광 재질의 합성 샘플을 사용할 수 있다. 실제 빛샘 데이터는 해당 Ray Tracing 실행의 광학 물성을 유지한다. 한편 세트 외관에는 사용자가 고른 색과 무광/반광 등의 표시 재질을 간단히 적용한다. 이 선택으로 원본 광학 profile·assignment를 변경하거나 재해석하지 않는다. 외관 표시 프리셋을 실제 재료의 반사 특성 검증 결과라고 설명하지 않는다. 광학 조건 자체를 바꾸려면 기존 Ray Tracing 흐름에서 새 결과를 만든다.

### 암실에서 제품 위치 확인

빛이 닿지 않는 외관은 어두워져야 한다. 현재 CAD 보기의 HemisphereLight와 DirectionalLight를 암실 평가 영상에 그대로 넣지 않는다(`three-viewer-canvas.tsx:1956`).

위치를 파악할 수 있도록 선택 윤곽 또는 형상 확인용 보조보기를 옵션으로 제공한다. 보조 표시는 광학 계산·휘도 수치·크기 판정에 포함하지 않으며, 평가용 영상 저장 시 기본적으로 제외한다.

## 5. 모델별 비교

제품 모델/설계 Case를 A/B로 선택하고 각 모델에 저장된 관측 위치의 영상을 나란히 표시한다. 사용자가 모델별 관측 위치가 다를 수 있다고 명시했으므로 공통 카메라 위치를 필수 조건으로 두지 않는다.

모델별로 `관측 이름 / 대상 코너 / 관심점 / 스크린 기준면 / 카메라 위치·방향 / 회전 중심 / 거리·각도 / 화각·해상도`를 저장한다. 이름 있는 관측점을 여러 개 등록할 수 있도록 계약을 잡고 첫 UI는 하나의 관측점으로 시작할 수 있다. 모델 ID와 연결하며, 다른 원점이나 형상을 가진 모델로 관측 좌표를 그대로 복사하지 않는다.

비교 목적은 다음 두 가지로 구분한다.

- **모델별 검사 위치 비교:** 각 제품의 실제 검사 위치를 사용한다. 기본 사용 흐름이며 관측 거리·각도 차이를 함께 표시한다. 보이는 크기·밝기의 차이에는 관측 조건의 영향도 포함된다.
- **관측 조건을 맞춘 비교:** 선택한 모델들의 코너 기준 상대 위치·거리·화각을 맞춘다. 구조 자체의 영향을 살피는 선택 기능이다. 동일 모델의 변경 전후 비교에서는 저장된 관측점을 유지할 수 있다.

공통 비교 프로필과 모델별 결과에는 다음을 저장한다.

- 외부 조명 0 조건, TV 동작 상태, 광원 입력의 비교 기준.
- 관측 거리·각도·화각·해상도·제품 정렬 기준.
- 최소 표시 휘도, 전이 구간, 노출·화면 변환, 보정 버전.
- 지원 광학 모델, 계산 품질, 원본 모델과 설정 버전.

모델의 부품 원점이나 크기가 다르면 제품 기준으로 정렬한다. 화면을 각각 꽉 채우는 자동 Fit으로 크기 비교를 하지 않는다. 각 모델의 실제 관측 거리·화각을 보존하고 화면상 크기는 그 조건에서의 투영 크기로 설명한다. 관측 거리가 다른 이미지의 픽셀 수만으로 실제 틈의 크기를 비교하지 않는다. 부분 확대는 사용한 확대 조건을 별도로 기록한다.

구조 차이를 비교할 때는 광원 조건을 맞춘다. 제품 전체의 실제 차이를 비교하는 목적이면 각 제품의 실제 광원 조건을 보존하고 차이를 기록한다. 서로 다른 제품의 발광 면적을 고려하지 않고 무조건 같은 총 lumen으로 맞추는 규칙을 강제하지 않는다.

기존 Case 저장·비교 UI와 조건 검사(`result-window.tsx:306`)를 활용하되 카메라·문턱·노출·보정 프로필까지 검사 범위를 확장한다. 모델별 검사 위치 비교에서는 카메라가 다르다는 이유만으로 비교를 막지 않고 조건 차이를 표시한다. 공통 표시 문턱·노출·변환은 유지하며, 문턱을 모델별로 달리 적용한 이미지는 공정한 가시 범위 비교로 취급하지 않는다.

## 6. 단계별 구현 제안

| 단계 | 구현 결과 | 검증 조건 |
| --- | --- | --- |

사용자가 함께 넣어 볼 첫 기능 묶음은 R0+R1로 잡고, 모델별 비교라는 핵심 목표를 위해 R2를 바로 다음 범위에 둔다. 초기 지원 광학 모델은 대표 빛샘의 지배 경로에 맞춰 정한다. 이미 저장된 Receiver 히트맵이나 표시용 Ray만으로 R1이 충족된다고 보지 않는다.

현재 원본 코드에서는 기존 결과로 재구성할 수 있는 관측 정보와 부족한 방향별 광학 정보를 구분하는 작업이 먼저 필요하다. 완료 run의 당시 입력·결과를 연결하고, 필요한 추가 데이터나 자동 보완 계산을 검증한다. 리시버 누적값을 그대로 외관 휘도로 사용하거나 기존 결과를 무시한 별도 전체 재해석을 기본안으로 확정하지 않는다. ROI 밖 형상과 해석 범위의 처리는 후속 검토 사항이다.

## 7. 첫 검증 장면

1. 무광 차폐판의 좁은 틈을 직접 바라보는 장면. 옆으로 돌렸을 때 실제로 가려지는지 확인한다.
2. 같은 형상에서 광원 출력만 낮춘 두 모델. 공통 화면 변환으로 밝기 차이가 유지되는지 확인한다.
3. 같은 밝기의 폭이 다른 틈. 공통 문턱·거리에서 보이는 폭이 구분되는지 확인한다.
4. 여러 약한 기여가 합쳐져 문턱을 넘는 장면. 개별 ray 절단으로 놓치지 않는지 확인한다.
5. 작은 밝은 점과 넓은 미광, 표본이 적은 장면. 크기만으로 진짜 빛샘을 삭제하거나 잡음을 빛샘으로 확정하지 않는지 확인한다.

사내 관찰 거리는 5~20 cm의 수직거리, 약 20~40 cm의 직선거리이며 각도는 스크린 법선 기준 10~30°로 확정되었다. 기하학적으로 가능한 조합을 초기 카메라 프리셋으로 제안하고, 최소 표시 문턱은 경계 수준의 기준 샘플을 확보한 뒤 보정한다. 보정되지 않은 결과는 실험용 추정으로 유지한다.

### 외부 개발용 레퍼런스

기존 코너 생성기를 기반으로 회사의 실제 도면·치수를 복제하지 않는 일반화한 시험 장면을 만든다. 틈 폭·길이·겹침 깊이·반사 조건을 독립적으로 조절하고, 완전 차폐·직접 노출·반사 누설·시점에 따른 가림·점형 빛샘·문턱 근처 광량을 시험한다. 코너 절단 경계에서 가짜 빛샘이 생기지 않도록 경계 조건을 정의한다.

형상과 입력값이 알려진 단순 장면에서 예상 결과를 비교하고, 복잡도를 늘려 간다. 간단한 장면의 해석적 결과를 렌더러 검증에 사용하는 방법은 [PBRT의 광전달 검증 설명](https://www.pbr-book.org/4ed/Light_Transport_I_Surface_Reflection/The_Light_Transport_Equation)을 참고한다.

합성 장면으로 확인할 대상은 다음과 같다.

1. 관측 방향별 가림·반사·발광 계산, 알려진 광원 변화에 대한 선형 원본 응답.
2. 틈의 투영 크기, 카메라 회전·거리 변경, 표본 수·영상 해상도 증가에 따른 안정성.
3. 공통 표시 문턱과 고정 노출, 원본 값 보존, 미광과 잡음의 구분 상태.
4. 모델별 관측점 저장·복원, 다른 형상·원점의 A/B 비교, 설정 오염 방지.
5. 일반화한 큰 모델로 기능 부하 확인. 실제 사내 CAD의 속도를 보장하는 결과로 사용하지 않는다.

### 사내 검증과 보정

외부에서 개발한 프로토타입을 사내 PC에 전달해 실제 모델로 실행한다. 실제 CAD·실측 영상·보정값은 사내에 보관하며 외부 전송을 개발의 필수 절차로 두지 않는다.

사내에서 확인할 항목은 실제 CAD 로딩과 미세 틈의 형상 정합, 실제 광원·재질을 반영한 절대 휘도, 보이는 경계와 폭·길이, 모델별 검사 위치에서의 결과, 실행 시간과 안정성이다. 특히 초기 참고값인 최대 1~2 nit와 최소 표시 문턱의 정합은 내부 실측으로 확인해야 한다.

피드백은 사내 정책상 공유 가능한 경우에 한해 현상 설명·일반화한 재현 조건·허용된 지표를 사용한다. CAD에서 일부를 잘라내거나 이름을 지웠다고 반출 가능하다고 가정하지 않으며, 이미지·로그·좌표·파일 경로도 자동 전송 대상으로 두지 않는다. 외부 공유가 전혀 불가능하면 내부 시험표와 보정 설정으로 검증을 완료하고, 외부 개발에서는 합성 장면의 검증 범위만 주장한다.

권장 작업 흐름은 `합성 코너에서 기능·계산 검증 → 사내 실제 모델 적용 → 내부 실측 비교·보정 → 공유 가능한 현상은 합성 장면으로 재현해 수정`이다. 사내 CAD 부재는 기본 개발의 차단 요인이 아니지만 실제 제품 정확도 확정에는 내부 검증이 필요하다.

## 9. ROI 경계와 완전 차폐 검증

이 절은 앞선 ROI 논의와 시험 결과를 보존한다. 사용자의 최신 지시에 따라 구체적인 ROI 구현은 Result 연계·자유 시점 3D 관측 방식을 확정한 뒤 검토한다. 아래 원칙을 이유로 별도 해석 설정 흐름을 되살리거나 원래 완료 결과와 다른 범위를 조용히 적용하지 않는다.

사용자는 닫힌 세트의 LCD/데코 이격만 실제 출구이며, ROI를 잘라 만든 경계가 가짜 출구가 될 수 있음을 지적했다. 현재 코드에서는 ROI가 추적용 mesh의 face를 제외한다(`raytrace_bridge.py:47`, `:123`). 화면에 보이는 ROI 단면 cap은 viewer용이며 광학 차폐면이 아니다(`three-viewer-canvas.tsx:3515`). 따라서 현재 ROI를 관측 범위 지정 기능으로 간주하여 그대로 렌더링에 연결하면 안 된다.

앞서 검토한 ROI 처리 원칙은 다음과 같다. 최종 데이터 연계 방식에 맞춰 후속 검토한다.

1. **광학 해석 형상:** 실제 차폐·반사 경로를 포함하는 전체 형상을 유지한다.
2. **관측 ROI:** 카메라가 살펴볼 코너와 결과 표시 범위를 지정한다. 이를 바꿔도 광학 형상을 삭제하지 않는다.
3. **Receiver:** 기존 측정값과 경로 진단에 사용한다. 다른 방향으로 빠진 광선을 숨겨도 손실된 반사·재유입 경로는 복구되지 않으며, 가짜 개방부를 지난 광선이 목표 Receiver에 도달할 수도 있다.
4. **관측 영상:** 가상 카메라의 위치·방향과 픽셀에 따른 광량을 계산한다. 기존 Receiver의 방향 정보 없는 누적 광속이나 개수가 제한된 저장 경로를 영상 밝기의 원본으로 쓰지 않는다.
5. **축소 해석:** 필요한 경우 경계에서의 유입·유출·반사 조건을 별도 모델로 정의하고, 전체 형상 또는 범위를 넓힌 결과와 비교한다. 임의의 검정 cap이나 반사 cap은 실제 외부 영역의 일반적인 대체물이 아니다.

ROI 밖 형상도 관측점의 입사광에 영향을 준다는 판단은 [PBRT의 광전달 방정식 설명](https://www.pbr-book.org/4ed/Light_Transport_I_Surface_Reflection/The_Light_Transport_Equation)과 일치한다. 기존 ROI 기능의 동작 변경은 이번 샘플 제작에 포함하지 않았다.

### 기존 Ray Tracing 속도 보존

사용자는 전체 형상을 보존하는 원칙을 새 렌더링에만 적용하고, 이미 개선한 기존 Ray Tracing 속도를 유지해야 한다고 명시했다. 다음은 구현 요구사항이며, 성능 검증을 이미 완료했다는 뜻은 아니다.

- 기존 `Run Ray Tracing`은 현재의 ROI 해석 범위와 최적화 경로를 유지한다. 렌더링을 위해 전체 형상 계산을 기존 실행에 덧붙이거나 전체 해석으로 자동 전환하지 않는다.
- 완료 결과에서 3D 빛샘 보기를 열면 해당 run에 필요한 관측 데이터를 준비하고 시점 변경에 맞춰 자동 갱신한다. 별도 Render 실행이나 광학 조건 입력을 요구하지 않는다. 닫힌 3D 보기의 무거운 작업을 계속 돌리지 않으며, 결과 확장에 필요한 수집 비용도 기존 해석 성능과 함께 검증한다.
- 일반 해석과 렌더링의 계산 작업은 기본적으로 동시에 돌리지 않는다. 기존 해석을 시작하면 진행 중인 렌더링 누적을 안전한 지점에서 중지·일시정지하고 자원 사용을 정리한 뒤 해석을 시작한다. 렌더링이 연산 자원을 점유한 채 뒤에서 계속 실행되어 기존 해석을 느리게 만들지 않도록 한다.
- 렌더링용 전체 mesh·가속 구조 준비와 캐시 사용을 기존 해석의 설정·결과·캐시 수명과 구분한다. 렌더링 종료 후 남은 메모리 점유나 캐시 교체로 일반 해석이 느려지는 경우도 성능 회귀로 확인한다.
- 기존 ROI 해석 결과는 범위 밖 경로가 빠져 있을 수 있으므로, 이를 전체 형상 기반 결과라고 표시하지 않는다. ROI 처리는 후속 검토하며 자동 보완이 원래 실행의 범위를 바꾸는 경우 결과의 관계를 명확히 정의한다. 준비·갱신 시간과 조작 중 미리보기 성능은 실제로 검증한다.
- 구현 전후 동일한 장면·ROI·광원·ray 수·백엔드에서 기존 해석의 결과와 소요 시간을 비교한다. 렌더링을 사용하지 않은 상태뿐 아니라 사용 후 일반 해석으로 복귀한 상태도 확인한다. 실제 측정 전에는 기존 해석과 새 렌더링의 속도를 같다고 보장하지 않는다.

### 로컬 시험 파일

`samples/closed_enclosure`에 회사 CAD를 사용하지 않은 불투명 조립체 STEP 4종과 대응 BITSAM 설정·결과를 생성했다. 생성기는 `scripts/generate_closed_enclosure_samples.py`다. 내부 1 lm 시험 광원, 동일 seed, 20,000 primary rays, 최대 깊이 4, CPU 조건으로 실제 STEP importer와 ray tracer를 실행했다.

| 장면 | 외부 Receiver 도달 수 | 총 수광 광속 |
| --- | ---: | ---: |
| 완전 차폐 | 0 | 0 lm |
| LCD/데코 0.2 mm 코너 틈 | 12 | 0.000292841 lm |
| LCD/데코 0.5 mm 코너 틈 | 118 | 0.00216193 lm |
| 완전 차폐 CAD의 일부를 절단 | 13,152 | 0.0826712 lm |

절단 샘플은 공기 공동을 열어 놓은 음성 대조군이며, 현 UI의 ROI face 선택을 정확히 재현한 것은 아니다. 이 샘플에서는 전면 실제 틈이 없는데도 전면 Receiver에 3,990건이 수집되었다. 절단면에 Receiver를 두지 않는 것만으로 목표 면의 가짜 수광을 막을 수 없음을 보여준다.

이 수치는 제한된 표본의 기하·광속 검증이며 실제 TV의 nit 또는 육안 밝기 보정 결과가 아니다. 특히 0.2 mm 틈은 도달 수가 적어 정확한 밝기·비율을 평가하려면 표본 수와 반사 깊이에 대한 수렴 확인이 추가로 필요하다. 상세 조건과 열기 방법은 [샘플 안내](../samples/closed_enclosure/README.md)를 따른다.
