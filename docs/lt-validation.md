# LT 결과 검증 모듈

시뮬레이터의 **Result → LT 검증**에서 엽니다. CAD나 현재 해석 결과가 없어도
사용할 수 있습니다. 비교 파일 읽기는 현재 프로젝트·CAD 캐시·해석 작업을 바꾸지
않습니다. 이 모듈은 결과 수치와 비교 가능 여부를 제공하며 합격/불합격을 판정하지 않습니다.

## 사용 순서

1. Case를 추가하고 이름을 지정합니다. Before/After/Case2에 한정되지 않습니다.
2. Simulator 쪽에 결과가 포함된 `.bitsam`, LightTools 쪽에 `.lts` 또는 저장한
   LT 데이터 JSON을 선택합니다. 리시버가 여러 개면 각각 비교 대상을 선택합니다.
3. LT 원시 표 또는 확인하지 못한 조건은 **LT 원시 입력 / 조건 보완**에서 입력합니다.
   총광속은 셀 합계와 별개로 입력합니다. 좌표 포함 표는 U/V 중심좌표로 정렬하며,
   좌표 없는 표는 행·열의 좌표 순서를 명시적으로 확인해야 합니다.
4. 기준 Case를 고르고 **전체 비교**를 누릅니다. 경고에 표시된 원시값·단위·조건이
   확인되지 않으면 수치는 참고용 총량만 표시하고 분포 비교는 차단합니다.
5. **세션 저장/열기**로 입력한 여러 Case를 JSON으로 보관할 수 있습니다. 창 닫기와
   웹페이지 새로고침은 다릅니다. 페이지 새로고침 전에 세션을 저장하세요.

설명은 화면의 `(?)` 도움말에 있습니다. 누락 값을 Simulator 쪽에서 자동 복사하지 않습니다.

## 계산 및 비교 조건

- 수광량은 `Σ셀 flux (lm)`입니다. ray 개수로 대체하지 않습니다.
- 조도는 `셀 flux / (ΔU × ΔV × 10⁻⁶)` lx입니다. U/V는 mm입니다.
  셀에 포인터를 올리면 비율과 lm/lx를 확인할 수 있습니다. nit와 혼용하지 않습니다.
- 원시 LT `setSumsMesh × IntegrationInterval`을 셀 flux로 변환합니다.
  합계가 저장된 `TotalPower`와 맞지 않으면 차단하며 강제 스케일 보정하지 않습니다.
- 수광량 편차는 `(Simulator / LT − 1) × 100%`입니다.
- 각 map은 자체 총합을 1로 정규화합니다. Pearson은 모든 셀을 대상으로 하며,
  중첩률은 `Σmin(Sim, LT) × 100%`입니다. 차이맵은 `(Sim − LT) × 100` %p입니다.
- Column은 V 방향 합산, Row는 U 방향 합산입니다. 각 그래프 곡선의 합계는 100%입니다.
- 기준 대비 비율은 각 도구 자체의 기준 Case를 100%로 합니다. 기준 Case와 광원·수광
  조건이 달라지면 해당 도구의 상대 비교도 차단합니다.
- 0 총량은 정규화 불가입니다. 일정한 격자의 Pearson은 정의되지 않아 `—`로 표시합니다.

리시버 위치, 유효 수광 법선, 수광 허용 **반각**, 크기, U/V별 격자 수·셀 경계,
광원 위치·방향·크기·광속 기준·방사 분포·Aim 조건을 검사합니다. 격자를 보간하거나
재배치해서 해상도를 맞추지 않습니다. 저장된 좌표축의 부호가 다른 경우는 실제 셀
좌표가 일대일로 일치하는 경우에만 대응합니다. 상관계수로 반전 방향을 선택하지 않습니다.
U/V별 격자 수가 다르면 차단하므로 25×15와 15×25도 직접 비교하지 않습니다.
위치·축 허용오차는 10⁻⁶ mm / 10⁻⁶, 일반 수치 상대 허용오차는 10⁻⁶입니다.
사진 총광속의 표시 반올림이 확인된 경우 최대 5×10⁻⁸ lm 절대 허용량을 입력할 수 있습니다.

## 입력 지원 범위

`.bitsam`은 ZIP의 `manifest.json`과 `project.json`만 읽습니다. project.json 크기,
CRC, SHA-256과 manifest 구조를 검사하지만 CAD·scene payload의 전체 무결성을
검증하거나 압축을 해제하지 않습니다. 기존 JSON 형식도 읽습니다. 저장된
`analysis_result.receivers / emitters / receiver_grids`를 사용하며 편집 중 workspace
설정으로 결과의 누락 조건을 대신하지 않습니다.

`.lts`는 텍스트 ORACAD 형식의 Forward Illuminance 저장 mesh를 읽는 초기 지원입니다.
파일 명령을 실행하지 않습니다. 실제 설치 예제의 8.2.0 / 8.3.2 / 2024.09에서 원시
누적값과 TotalPower 검산을 확인했습니다. **2025.03 실제 파일 지원은 아직 검증되지
않았습니다.** Radiometric은 저장 FluxUnits가 Lumen이어도 lm로 취급하지 않습니다.
Photometric·Lumen·Incident를 확인한 데이터만 lm 값으로 제공합니다.

ORACAD 저장 배열 순서와 세계좌표 변환은 확인 자료가 부족해 자동 확정하지 않습니다.
추출한 flat 배열은 검산된 값과 저장 치수를 보존하며, 사용자가 확인한 U/V 순서 및
셀 경계로만 연결할 수 있습니다. 방향·수광 조건·광원 조건은 별도 확인이 필요합니다.
미확인 상태 자체를 '동일 조건'으로 처리하지 않습니다.

현재 광원 조건 비교는 사각 평면 광원과 사각 Aim Area를 중심으로 지원합니다.
Gaussian 폭, 다각형 광원, 구면 Aim, 양면 방사 등 표현되지 않은 조건은 차단합니다.
독립 형식 정의는 [lt-validation-contract.md](lt-validation-contract.md)를 참고하세요.

## 실제 결과 검증에 필요한 자료

동일 조건의 결과가 포함된 `.bitsam`, LT의 Unsmoothed 셀값 및 총광속,
리시버 세계좌표·로컬 축·수광 법선·허용각과 광원 설정이 필요합니다.
Smoothed 표와 미확인 조건만으로 실제 LT 정합을 판정하지 않습니다.
사용자 프로젝트, 촬영 자료, 실제 결과와 케이스별 검토 기록은 저장소에 포함하지 않습니다.
