# 임시 AI 검토 파일

일반 사용자 UI를 추가하지 않는 현장 개발 진단용 기능이다. 새 광선 추적이나 설정 변경, 자동 업로드는 하지 않는다.

1. 같은 프로젝트에서 Preview 계산을 완료하고 검토할 Leak Point를 선택한다.
2. 경로 검증 및 동일 센서 광량 비교를 실행한다. 이미 결과가 있으면 다시 실행할 필요 없다. 별도 순방향 진단 결과도 있으면 포함된다.
3. Whole Set Lighting / Preview 패널을 연 상태에서 브라우저 개발자 도구(F12)의 Console에 다음을 실행한다.

```js
await window.exportLeakAiReview()
```

다운로드 폴더에 `leak-ai-review-날짜.json` 하나가 저장된다. 성공 시 콘솔에 파일명·크기·증거 누락 목록이 반환된다. 패널을 닫으면 명령도 해제된다. 새 버전 적용 전 브라우저를 새로고침하면 메모리의 결과가 사라질 수 있으므로 경로 검증의 재생 JSON과 광량 비교의 검증 JSON을 각각 저장한다. 일반 프로젝트 저장에는 이 두 진단 기록이 포함되지 않는다.

파일에는 저장된 Preview 원본·선택 경로, 현재 검증 요청(광원·재질·센서·ROI·종료 조건), 경로 검증, 양방향 회차별 광량·실행 증거·순방향 진단, 일반 순방향 결과가 포함된다. 기본값은 대용량 CAD 표시 메쉬 제외이며, 형상 검토 불가를 evidence_gaps에 기록한다. 일부 기록이 없거나 조회가 실패해도 확보된 근거를 저장하고 `evidence_gaps`에 명시한다. 비교의 서버 저장 요청과 현재 요청의 일치 여부도 기록한다. 내보내기 시점의 UI 입력을 먼저 고정하며, API 결과는 별도 조회 시점의 상태이다.

CAD 표시 메쉬까지 포함하려면(파일 크기 및 메모리 사용량 증가):

```js
await window.exportLeakAiReview({ includeGeometry: true })
```

**파일에는 기구 좌표·부품명·재질·경로 및 로컬 경로 문자열 등 보안 정보가 포함될 수 있다.** 메쉬 제외도 익명화가 아니다. 보안 PC의 허용된 AI/검토 환경에서만 사용한다. 자동으로 외부 전송하지 않는다.

AI에는 “`payload.ai_review_instructions`와 `payload.ai_interpretation_guide`에 따라 검토해줘”라고 요청한다. 파일 안의 해석 가이드에 읽는 순서, 원본 데이터 위치, 항목별 의미, 원인 후보별 판단 조건, 답변 형식이 포함된다. AI는 실제 JSON 경로·회차·숫자를 근거로 결론 / 확인된 사실 / 원인 후보와 부족한 증거 / 다음 행동 하나 / 한계를 제시하도록 되어 있다. 가이드의 예시는 가상 사례로 표시되며 실제 결과로 취급하지 않는다. 기존에 내보낸 파일은 자동 변경되지 않으므로 새 가이드를 포함하려면 다시 내보낸다.

`payload_sha256`은 속성 순서를 보존한 UTF-8 `JSON.stringify(payload)`의 SHA-256이다. payload가 32 Mi UTF-16 코드 단위를 초과하면 체크섬 계산을 생략하고 null과 사유를 기록한다. 브라우저에서 Web Crypto를 사용할 수 없거나 체크섬 계산이 실패한 경우에도 동일하게 사유를 기록하고 진단 파일 저장을 계속한다. 파일 자체나 실물 정확도에 대한 인증이 아니다. JSON 파일은 작은 문자열 조각으로 생성하며 전체 파일을 단일 문자열로 만들지 않는다.

한계: 비교에서 전체 검출 Ray 궤적을 저장하지 않으므로 없는 궤적은 복원하지 않는다. 일반 순방향 결과는 당시 요청 동일성을 알 수 없다고 표시한다. CAD 표시 메쉬는 서버의 정밀 교차 메쉬와 동일하다고 보장하지 않는다. JSON은 재실행 가능한 프로젝트나 물리 검증 완료 증거가 아니다. 미완료·이전 조건의 결과도 원본으로 보존하되 함께 집계하지 않도록 표시한다.


오류 처리: 결과 조회가 30초 안에 끝나지 않거나 실패하면 해당 항목을 `evidence_gaps`에 기록하고 다른 확보된 기록을 저장한다. 서버 계산을 중단하거나 결과를 초기화하지 않는다. 파일 생성 중 같은 명령을 다시 실행하면 중복 실행을 막으며 첫 번째 실행은 계속된다. 다운로드 실패 후에는 명령을 다시 실행할 수 있다. 파일 생성 성공은 브라우저에 다운로드를 요청했다는 뜻이며, 다운로드 폴더에서 실제 파일을 확인해야 한다. 이 파일은 일부 자료가 누락된 상태일 수 있으므로 AI는 항상 `evidence_gaps`부터 읽어야 한다.
