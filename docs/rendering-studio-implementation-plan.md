# Ray Tracing 결과에 연결하는 3D 빛샘 보기 — 착수 계획

- 갱신일: 2026-09-07
- 상태: Result 연결 기반과 첫 자유 시점 3D 표시 수직 조각을 구현했다. 현재 표시는 저장된 수광 경로를 완료 실행의 변환 형상 외곽 경계와 교차시키는 개발 시제품이며, 실제 틈 면적·절대 밝기·일반 CAD 출구 검출은 아직 보정하지 않았다.
- 상위 요구사항: [암실 빛샘 렌더링 프로토타입 계획](darkroom-rendering-prototype-plan.md)
- 첫 목표: **Ray Tracing을 완료한 모델의 Result에서 3D 빛샘 보기를 열고, 조건을 다시 입력하지 않은 채 회전·확대하며 여러 각도의 빛샘을 관찰한다.**

### 1차 범위 — 절대 휘도 보정 없이 빛샘 외관 미리보기

사용자는 절대 nit 일치가 아직 필요하지 않고, 빛샘을 실제처럼 시인할 수 있는 1차 구현을 원한다고 범위를 구체화했다. 핵심은 **실제 틈의 위치와 모양, 시점에 따른 기구 가림, 근거가 있는 방향별 표시**다. 절대 밝기·육안 검출 한계·정확한 가시 면적 보정은 후속으로 둔다. 이 완화가 광학 근거 없이 빛을 그리거나 다른 틈에 표시해도 된다는 뜻은 아니다.

세트 외관은 사용자가 고른 검정/회색 등의 색과 무광/반광 정도를 표시 재질에 적용한다. 기존 광선 추적의 광학 물성과는 별개인 외관 표현이며, 색·마감 변경으로 완료 결과의 광원·물성을 바꾸거나 재해석하지 않는다. 외관 표현을 실물 재질의 정밀 광학 검증 결과라고 설명하지 않는다.

첫 개발은 작은 합성 코너의 **Result 연결 → 실제 출구에 빛샘 표현 → 회전/가림 → 간단한 외관 변경**까지 진행한다. 새 범용 카메라 path tracer와 절대 cd/m² 출력은 이 시제품의 선행 조건으로 두지 않는다. 정확한 방향 정보가 부족한 부분은 결과 데이터 보강 대상으로 남기고, 근거 없는 전방위 밝기를 만들어내지 않는다.

## 1. 확정한 사용 흐름

`기존 CAD/광원/광학 물성 설정 → Ray Tracing 실행·완료 → 해당 Result에서 3D 빛샘 보기 → 회전·확대·이동하며 관찰`

렌더링은 해석 결과를 보여주는 표현 방식이다. 별도 상단 Studio 진입점, 새 모델 가져오기, 광원·물성·광선 수 재설정, 카메라를 바꿀 때마다 Render를 누르는 흐름은 채택하지 않는다. Rendering Studio라는 명칭을 사용하더라도 Result의 연장으로 제공한다.

사용자는 모델 전체 또는 코너를 중심으로 자유롭게 돌려본다. 새 시점에 맞는 가림과 빛의 방향 특성이 화면에 반영돼야 한다. 고정 이미지 한 장을 회전시키거나 단순한 CAD 회전만 제공하는 것은 완료 조건을 충족하지 않는다. 이미지 저장은 부가 기능이다.

첫 UI의 필수 조작은 3D 보기 열기/닫기, 회전·확대·이동, 회전 중심 지정, 기준 시점 복귀다. 거리·각도 수치 입력이나 관측점 저장은 관찰을 돕는 선택 기능이며 영상을 보기 위한 선행 설정으로 요구하지 않는다. 환경은 초기 암실 기준을 자동 적용한다. 공통 표시 문턱과 노출은 표시 프로필로 적용하고 해석 조건 입력 화면을 반복하지 않는다.

## 2. 무엇을 이어받는가

선택한 결과의 `run_id`와 **그 결과를 생성한 당시의 입력**을 기준으로 다음을 연결한다.

- CAD 내용과 형상 revision, 실제 적용 transform, 해석 범위와 부품/면의 식별.
- 광원의 위치·형상·방향·출력·배광.
- 광학 profile, 부품/면 assignment와 우선순위, 해당 실행의 광학 계산 모델.
- 해석 설정과 완료 상태, 수광 결과 및 3D 관측에 사용할 수 있는 기존 데이터.

렌더링을 여는 순간의 수정 가능한 workspace 설정을 과거 결과와 섞지 않는다. 해석 후 광원·재질·형상을 바꿨다면 기존 3D 결과는 원래 완료 실행에 연결된 상태로 유지한다. 새 조건은 기존 Ray Tracing 흐름에서 새 결과를 만든 뒤 연결한다.

내부 모듈이나 관측 캐시를 별도로 두는 것은 가능하지만 사용자가 새로운 해석을 설정하는 제품 흐름과는 구분한다. 실제 결과 연계에서 기존 광학 모델을 임의의 상수 Lambertian 재질 등으로 조용히 교체하지 않는다. 단순한 광학 모델은 개발용 정답 검증 장면에 사용할 수 있을 뿐, 완료 결과의 물성을 바꾸는 근거가 아니다.

## 3. 첫 기술 작업: 결과 데이터의 연결과 충분성 확인

현재 `RayTraceResult`에는 `run_id`, config, emitters, receivers, optical_profiles, Receiver 격자, 제한된 stored_paths 등이 있다(`frontend/src/api/types/raytrace.ts:232`). 형상·transform·assignment까지 결과 생성 당시 상태로 완전히 재현할 수 있는 연결은 추가 확인·보강이 필요하다.

첫 작업은 다음 세 가지다.

1. 완료 결과와 당시 CAD·광학 입력을 정확히 연결하는 불변 스냅샷/참조 계약을 만든다. 세션 token이나 현재 workspace만으로 과거 결과를 복원하지 않는다. 현재 BITSAM 지문은 0.2/0.5 mm 샘플을 구분하지 못하므로 그 값만으로 결과·캐시를 연결하지 않는다.
2. 기존 결과에서 자유 시점 3D 관측에 재사용할 수 있는 값과 부족한 위치·방향별 광학 정보를 구분한다. Receiver의 누적 광속과 일부 저장 ray만으로 임의 시점의 밝기와 가림을 완전히 복원할 수 있다고 가정하지 않는다.
3. 필요한 최소 추가 데이터를 어떻게 확보할지 검증한다. 결과 데이터 확장, 결과에서 파생하는 관측 캐시, 동일 실행 입력에 기반한 자동 보완 계산 등을 후보로 비교한다. 기존 결과를 무시하고 매번 전체 해석을 다시 하는 방식을 기본안으로 확정하지 않는다.

보완이 필요하더라도 광학 조건은 해당 실행에서 그대로 가져온다. 사용자에게 광원·물성·ray 수 등을 다시 입력하거나 각도마다 재해석을 누르게 하지 않는다. 기존 저장 결과에 충분한 정보가 없는 경우에는 자동 복원이 가능한지 확인하며, 불가능한 정보를 있는 것처럼 표시하지 않는다.

현재 데이터만으로 추가 계산 없이 모든 각도를 즉시 볼 수 있는지, 어떤 방식이 속도·메모리·정합을 만족하는지는 아직 검증하지 않았다. 이 불확실성을 먼저 해결하되 제품 목표인 결과 연계와 자유 시점 조작을 정지 이미지 기능으로 축소하지 않는다.

## 4. 3D 화면과 자동 갱신

- 기존 Result에서 선택한 Case/run에 연결되는 `3D 빛샘 보기` 진입점을 둔다. 구체적인 탭·패널 배치는 결과 화면과 함께 설계한다.
- 열 때 필요한 관측 데이터를 자동 준비하고, 마우스 조작에 맞춰 화면을 갱신한다. 초기 준비가 필요하면 같은 결과 보기 안에서 진행 상태를 표시한다.
- 조작 중 빠른 관측 미리보기, 조작을 멈추면 자동 품질 보완하는 방식을 검토한다. 새로운 각도에 실제로 맞는 영상인지 구분하며 오래된 프레임을 새 결과로 오인하게 두지 않는다.
- 카메라와 회전 중심은 결과에 부가되는 보기 상태다. 모델 transform이나 광원 좌표를 함께 회전시키지 않는다. 모델별 관측 위치도 저장할 수 있게 한다.
- 표시 문턱·노출 변경은 원본 광학 결과를 보존한다. 모델별 자동 밝기 정규화로 차이를 없애지 않는다.
- 외관은 표시용 색·무광/반광 프리셋을 사용자가 간단히 고른다. 이 값은 완료된 Ray Tracing의 광학 반사율·배광을 덮어쓰지 않으며 빛샘 결과를 바꾸는 해석 조건으로 보내지 않는다.
- 단순 CSS 숨김 뒤에서 기존 viewer와 새 viewport가 동시에 계속 그리지 않게 한다. 닫힌 결과 보기는 불필요한 작업과 메모리를 반환한다.

코드 연결 후보는 기존 `features/results/`와 viewer/workspace의 결과 표시 경계, 새 `features/rendering/`의 카메라·관측 캐시·표시 상태다. 내부 상태를 분리해도 기존 CAD 구독과 해석 결과의 수명은 유지한다.

### 첫 시제품의 데이터와 표시 방법

현재 결과의 수광 직전 두 점으로 마지막 진행 방향을 복원할 수 있다. 그러나 마지막 반사점은 내부 부품일 수 있고 Receiver 점은 측정면이므로 둘 중 하나를 그대로 제품의 빛샘 위치로 표시하지 않는다. 공기 중 틈을 통과하는 순간은 충돌 사건이 아니어서 실제 출구 좌표가 별도로 저장돼 있지 않다.

첫 합성 코너에서는 알려진 외면 Z=18 mm와 마지막 진행 선분의 교점을 사용한다. 기존 0.2 mm 샘플의 저장된 수광 경로 12개, 0.5 mm 샘플의 118개가 모두 실제 L자 틈 안을 통과함을 확인했다. 이 대응으로 출구 위치·진행 방향·상대 에너지·원본 경로 ID를 담는 작은 표시용 데이터를 만드는 것부터 착수한다. 일반 CAD의 출구 자동 식별은 별도 검증이 필요하다. 샘플의 Z값을 다른 제품에 일반화하지 않는다.

후속 3D 표시는 해당 출구 데이터와 검증된 틈 형상에 기반한 작은 발광 영역으로 구현한다. 화면을 따라 움직이는 큰 sprite나 과도한 bloom으로 틈의 위치·폭을 바꾸지 않는다. 점 표본을 보기 좋게 연결한 부분은 추정이며 실제 검출된 연속 영역으로 단정하지 않는다. 방향별 정보의 부족도 별도로 다룬다.

출구 추출의 첫 구현은 `scripts/extract_closed_enclosure_leakage_samples.py`에 추가했다. 기존 결과 파일만 읽어 `samples/closed_enclosure/leakage_preview_samples.json`을 생성하며, Ray Tracing을 다시 실행하지 않는다. 닫힌 샘플 0개, 0.2 mm 틈 12개, 0.5 mm 틈 118개를 추출했고, 유한한 값·단위 방향·원래 선분 위 교점·알려진 틈 내부 여부를 검사했다. 이 데이터는 개발용이며 아직 Result 화면에 연결하지 않았다.

CAD의 깊이 가림을 적용하고, 현재 ray 선분의 항상 위에 그리는 방식(`depthTest:false`)을 사용하지 않는다. 외관은 불투명 깊이를 유지해 뒤쪽 빛이 차폐면을 뚫고 보이지 않도록 한다. 표시용 ray 좌표에는 이미 당시 transform이 반영돼 있으므로 다시 변환하지 않는다. 외관의 색·거칠기와 깊이 가림은 기존 Three.js 재질 기능을 활용할 수 있다([MeshStandardMaterial](https://raw.githubusercontent.com/mrdoob/three.js/dev/src/materials/MeshStandardMaterial.js), [Material](https://raw.githubusercontent.com/mrdoob/three.js/dev/src/materials/Material.js)).

저장 경로는 제한된 수광 우선 표본이다. 경로 개수·상대 에너지의 단순 합을 전체 광량, 정확한 면적, 모델 간 개선율로 사용하지 않는다. 표본에 없는 방향은 실제로 어둡다는 뜻이 아니다. 시제품에서 위치·가림·표시 흐름을 확인한 뒤 필요한 출구/방향 데이터를 선택 편향과 저장 상한을 고려해 보강한다.

## 5. 기존 해석 속도 보호

기존 Ray Tracing의 ROI 해석과 최적화 경로를 유지한다. 3D 보기 준비와 시점 갱신 때문에 일반 해석이 뒤에서 자원 경쟁을 겪지 않게 한다. 새로운 Ray Tracing 실행은 우선 처리하고, 필요한 관측 작업은 안전한 경계에서 중지·정리한다.

결과 확장에 추가 수집이 필요하다면 저장량·계산량의 증가부터 측정한다. 모든 ray 경로를 무조건 보존하거나 모든 방향을 선계산하는 것으로 결정하지 않는다. 3D 보기를 열지 않는 사용자까지 항상 큰 계산 비용을 부담하게 만들지 않는 방식을 우선 검토한다.

성능은 기존 해석 시간뿐 아니라 3D 보기 최초 준비 시간, 회전 중 반응, 정지 후 품질 회복, 메모리 점유, 보기 종료 후 일반 해석 성능을 함께 확인한다. 측정 전에는 기존 완료 결과만으로 즉시 고품질 자유 시점 렌더링이 가능하다거나 기존 해석 속도가 그대로 유지된다고 단정하지 않는다.

## 6. 착수 전 수정 로드맵

사용자가 구현 착수 전에 검토한 단계별 계획이며 현재 0단계, 1단계와 2단계의 핵심 3D 표현까지 구현했다. 2026-09-07 외관 밝기·색·마감 설정과 가시성 개선, 평면 틈 내부의 에너지 보존 연속광 재구성을 추가했다. 단계별 완료 조건을 기준으로 일반 도면 확장을 이어 간다.

**첫 확인 지점인 2단계 핵심 시각화는 완료했다.** `gap_0p5`의 완료 Result에서 3D 보기를 열고, 추가 광학 설정이나 각도별 Render 클릭 없이 코너 빛샘을 돌려보며 연속 표현과 방향 감쇠를 확인했다. 이 단계는 합성 샘플에서 결과 연결·표시·가림을 검증하는 시제품이다. 일반 CAD나 모든 방향의 정확한 밝기 재현을 완료했다고 판단하지 않는다.

2단계부터 암실 배경과 공통 상대 표시 스케일을 적용한다. 아주 약한 표시를 숨기는 문턱은 공간·방향별 누적 표시값에 적용하는 실험값으로 다루며, 개별 ray 종료 조건을 바꾸지 않는다. 표본이 부족한 영역을 실제 비검출로 해석하지 않는다. 모델마다 자동 노출로 밝기를 맞추지 않으며, 절대 nit나 검출 한계로 표기하지 않는다. 외관 색·마감은 표시 설정이고 해석에 사용한 광학 물성을 덮어쓰지 않는다.

3단계의 데이터 충분성 판단은 1단계부터 시작한다. 제한된 저장 ray만으로 필요한 관측 방향을 표현할 수 없다면 최소한의 결과 데이터 보강이나 자동 준비 방법을 검증한다. 방향 정보가 없다는 이유로 해당 방향을 어둡게 단정하거나 모든 방향에 같은 발광을 만들어내지 않는다. 전체 Ray Tracing을 반복하는 방식이나 모든 ray 경로 저장을 기본안으로 확정하지 않는다.

성능은 각 단계에서 점검하고 4단계에서 최종 확인한다. 기존 일반 해석 속도 보호는 전 단계 요구사항이다. ROI 정책은 사용자의 요청대로 3D 결과 보기 방식을 확인한 뒤 검토하며, 그 전까지 절단된 ROI 결과의 인위적 유출을 실제 빛샘처럼 취급하지 않는다. 기존 결과와 다른 해석 범위를 자동으로 적용하는 결정도 여기서 미리 내리지 않는다.

UI와 데이터 검증은 필요한 계약을 공유한 뒤 병행할 수 있다. 고정 카메라 영상은 개발 검증에 사용할 수 있지만 첫 사용자 기능의 완료 기준은 자유 시점 3D 보기다. 자동 설계·차폐 구조 추천은 빛샘 시뮬레이터 V1이 완전히 개발 완료된 뒤 별도 후속 버전으로 진행한다.

## 7. 첫 제품의 검증 기준

1. `gap_0p5`의 Ray Tracing을 완료한 Result에서 조건 재입력 없이 3D 빛샘 보기를 연다.
2. 마우스로 정면·사선 등 여러 각도로 움직이면 해당 각도의 가림과 빛샘이 자동 갱신된다. 이미지 회전이나 CAD만의 회전으로 대체하지 않는다.
3. 광원·광학 물성·형상은 해당 완료 실행의 값과 같다. 외관용 표시 색·마감은 별도 보기 상태로 바꿀 수 있다. 다른 결과를 선택하면 정확히 그 실행으로 전환된다.
4. `closed`의 외부 빛샘은 보이지 않고, 실제 틈이 보이는 시점에서는 그 투영 위치에서 빛을 관찰한다. 표시 조명·윤곽은 광학 밝기에 합산하지 않는다.
5. 광원 출력을 절반으로 바꿔 기존 흐름에서 다시 해석한 두 결과의 원본 상대 가중치와 공통 표시 변환이 일관되는지 확인한다. 표본 수 차이를 밝기 차이로 단정하지 않는다. 절대 nit 일치는 1차 합격 기준이 아니며 기존 결과 보기의 광원을 따로 편집하지 않는다.
6. 표시 문턱 변경은 원본 데이터를 바꾸지 않으며, 표본·해상도 부족을 실제 비검출로 확정하지 않는다.
7. 보기 닫기/열기, Case 전환, 새 해석 시작에서 기존 결과나 설정을 잃지 않고 이전 실행의 캐시를 잘못 재사용하지 않는다.
8. 기존 Ray Tracing과 3D 반응 성능을 실제로 확인한다. 첫 화면이 열리는 것만으로 성능 검증을 끝내지 않는다.

## 8. ROI와 후속 쟁점

사용자는 ROI 처리는 결과 연계와 3D 관측 컨셉을 맞춘 뒤 논의하자고 명시했다. 앞서 검토한 전체 형상 보존, 관측 ROI 분리, 절단 경계의 광학 문제와 합성 샘플 결과는 참고로 보존한다. 이번 착수안에서 ROI 정책을 먼저 확정하거나 기존 완료 결과와 다른 해석 영역을 조용히 적용하지 않는다.

ROI 밖 정보를 추가하는 계산은 원래 실행의 범위와 다를 수 있으므로 같은 결과인지 보완 결과인지 명확히 하는 계약이 필요하다. 구체적인 처리 방식은 후속 검토 사항이다.

모델별 관측 위치, 거의 0 lux 암실, 공통 미광 표시 기준, 사내 CAD 없이 합성 샘플로 개발한다는 기존 목표는 유지한다. 자동 설계는 V1 완료 이후다.


### 2026-09-07 연속광 보완
