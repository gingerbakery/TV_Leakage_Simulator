# Preview 유출 방향 집계

Preview의 `Detection Direction > 유출 방향 · Source sampling`은 최종 유출광을 선택 축 기준으로 집계한다. 후면은 `후면 -Z`를 선택한다. 새 Workspace는 이 방식이 기본이며, 이전 프로젝트에 방식 정보가 없으면 기존 평면 검출을 유지한다.

## 집계 기준

- 광선이 더 이상 기구물과 교차하지 않는 최종 구간에서만 집계한다. 중간 경계 통과나 재진입을 중복 집계하지 않는다.
- 모델 전체의 변환된 경계 상자에서 최종 출구 위치를 계산한다. 이 위치는 실제 홀 표면 위치와 다를 수 있다. 경계 상자를 통과하지 않는 외부 광원 경로는 제외한다.
- 선택 축과 광선 진행 방향 사이의 각도를 `0–30`, `30–60`, `60–80`, `80–90°`로 나눈다. 각 구간은 아래 경계 포함·위 경계 제외이며 마지막 구간만 90°를 포함한다. 부동소수점 각도 경계는 1e-10도 단위로 정리한다.
- 90° 접선 광선도 집계한다. 실제로 시뮬레이션한 광선 중 에너지·반사 횟수 제한으로 종료된 경로는 최종 유출로 간주하지 않는다.
- ALLOWED AREA는 개별 최종 유출 구간이 설정 영역의 경계 평면을 실제로 통과하는지 판정한 후 집계한다. 좌표가 없는 법선 축은 모델 경계 평면을 사용한다. 인접 빛샘을 숨기던 5 mm 확장은 적용하지 않고 수치 오차 허용값만 사용한다. 여러 유출 경로가 같은 칸에 들어가도 대표 위치 평균으로 제외 여부를 판단하지 않는다.
- 표의 광량은 전체 시뮬레이션 광선으로 집계하며 저장 경로 4,000개 제한에 의존하지 않는다. 유출 방향 모드에서는 양의 광량이 있는 모든 셀을 후보에 반영하며 상대 강도 임계값, 후보 8개 및 표시 점 800개 제한을 적용하지 않는다. 기존 평면 모드는 기존 제한을 유지한다. 관찰자 위치의 nit 계산은 아니다.

## CPU와 GPU

CPU와 GPU는 동일한 Source sampling 및 counter-RNG 배치 경로를 사용한다. GPU 선택 시 CUDA BVH가 교차 판정을 수행하고, 반사 진행·유출 방향 및 광량 누적은 공통 CPU 코드가 수행한다. GPU 전체 계산이나 속도 향상을 검증 없이 주장하지 않는다. 실제 실행 상태는 Preview 결과의 Compute 항목에서 확인한다. CUDA 성공 batch가 0이면 GPU 실행 성공이 아니다.

CPU scalar 기준, CPU 배치의 광량 보존·차폐·극각·BSDF 경로는 단위 테스트에서 점검한다. 실제 CUDA 정합은 GPU가 있는 PC에서 별도 검증해야 한다.

## 실제 CUDA 비교 검증

Git source는 `run_web_gpu.bat` / `run_web_gpu.ps1`으로 준비한 `.venv-gpu`를 사용한다. 필요한 GPU·드라이버·Toolkit 기준과 설치 승인 규칙은 `ai-gpu-execution-runbook.md`, `gpu-cuda-user-guide.md`, `WINDOWS_GPU_SETUP.md`를 따른다. 이 스크립트는 설치·서버 재시작·시스템 설정 변경을 하지 않는다. 다른 CPU/GPU 성능 측정이나 Ray Tracing과 동시에 실행하지 않는다.

```powershell
.\.venv-gpu\Scripts\python.exe scripts\verify_escape_direction_accuracy.py --rays 16384 --json-out artifacts\escape-direction-gpu-report.json
```

스크립트는 production FP64 Ray/BVH preflight의 available/strict_float64/kernel_executed/kernel_verified와 scope/contract를 확인한다. 하나라도 통과하지 않으면 계산을 시작하지 않고 실패 결과를 기록한다.

동일 장면·seed로 CPU와 GPU의 0°·45°·89.9°·반사·Face emitter·BSDF 반사 사례를 비교한다. GPU는 같은 장면 객체와 프로세스에서 첫 실행과 warm 2회를 기록한다. 각도별 수, 전체 수, 셀 위치·광량 등 전체 집계를 대조한다. 정수는 exact, 실수는 상대 1e-9/절대 1e-12 허용 오차를 적용한다. 각 실행의 CUDA 성공 수가 0이거나 유효 표본이 30 미만이면 통과하지 않는다. GPU 실행 증명과 물리 정확도·실측 보정은 별개다.

## 저장 호환성

이 방식의 `.bitsam`은 `bitsam-project.v1-escape1`로 저장한다. 이전 빌드가 방향 집계를 평면 검출로 조용히 바꾸지 않도록 별도 schema를 사용한다. frontend와 backend를 함께 갱신해야 한다. Git pull은 이미 추출한 ZIP/EXE를 갱신하지 않는다.


## 관찰 시야각 역추적

`시야각 역추적`을 켜고 좌우·상하 각도(-89.9~89.9°), 주변 범위, 각도 간격,
해상도 및 셀 반복을 입력한다. 선택한 축이 0° 정면이며 후면 -Z에서는 좌우 +가 +X,
상하 +가 +Y이다. 두 값은 방위각·고도각 조합으로 정의한다. 화면 카메라와 독립인 평행
관찰 방향이며 유한 거리 관찰자나 렌즈의 밝기 계산은 아니다.

각도 탐색은 중심, 범위 끝점 및 지정 간격을 포함한다. 극각 preset은 한쪽 81~89°와
그 주변을 검사한다. 반대쪽은 좌우/상하 값의 부호를 바꿔 검사한다. 각도 조합 최대
121개, 전체 관찰 ray 최대 500,000개로 제한하며 초과 시 명시적으로 실패한다.

관찰 화면 격자 중심과 추가 jitter뿐 아니라 광원 면적 가중 표본을 관찰 평면에 투영한
위치도 검사한다. 극각에서 광원 투영 폭이 격자보다 작아져 놓치는 직접광 경로를 보완한다.
모든 경로에 CAD와 Blocker 차폐를 적용한다. 반사점마다 광원 연결을 시도하고,
정반사·넓은 반구 proposal로 최대 반사 횟수까지 이어간다. 완성된 경로의 발광 방향,
반사 반구·정반사 조건·측정 BSDF의 실제 광원→관찰자 방향 support를 확인한다.
측정 BSDF의 상호성을 가정하지 않으며 analytic BSDF fallback을 하지 않는다.

이 기능은 `observer_path_support_v1` 경로 탐색이다. 경로 수는 lm/nit가 아니며 기존
광원 추적의 광량, Receiver hit count 및 에너지 수지에 합산하지 않는다. 광량에 대한
양방향 MIS 추정기 또는 실물에서 사람에게 보이는 밝기 판정으로 해석하지 않는다.
역추적은 Ray Tracing에서 선택한 CPU/GPU를 따른다. CUDA BVH는 관찰 1차 광선,
반사 후속 광선 및 광원 연결 차폐 광선을 배치 처리한다. 발광·반사·BSDF support 확인과
virtual Emitter 교차 및 집계는 CPU 공통 코드에서 수행한다. 광선별 독립 seed와 표본 순서
누적으로 batch 크기나 장치 스케줄이 샘플을 바꾸지 않는다.

역추적 결과 안의 별도 Compute 상태 및 CUDA 성공 batch 수를 확인한다. 기존 광원 추적의
GPU 성공은 역추적의 GPU 실행 증거가 아니다. 역추적 CUDA 성공이 0이면 CPU 대체 실행이며
UI에 표시한다. 성공 후 일부 실패가 있으면 혼합 실행으로 표시한다. 작은 후속 배치도 현재는
CUDA를 직접 시도하므로 workload에 따라 전송 비용이 커질 수 있다. 전체 GPU transport나
속도 향상을 실측 없이 주장하지 않는다.

ALLOWED는 첫 가시 면/광원 면과 관찰 평면 사이의 유출 구간에 적용한다. 후보 위치는
경계 상자가 아니라 처음 보이는 면이며, 내부 반사면 또는 광원일 수 있다. 각도별 직광·반사광
검출 수와 표본 간격(mm), 반사 한도 종료 수, 부분 실행 여부를 별도로 기록한다.
ROI에는 해당 관찰 각도와 방향을 저장하고 생성 Receiver도 해당 방향으로 배치한다.
일반 정밀해석 Receiver는 유한 면적의 입사 광량을 측정하므로 역추적의 평행 관찰과 동일한
밝기 측정기로 간주하지 않는다. 관찰 ROI가 하나라도 활성화된 정밀해석은 ROI 밖 차폐·반사 형상을 유지하도록 전체 CAD를 사용하며 UI에 표시한다. 따라서 작은 관찰 ROI도 전체 형상 준비 시간이 필요하다. 사용자가 TRACE OFF로 제외한 부품은 계속 제외된다.

미검출은 빛샘 없음의 증명이 아니다. 샘플링되지 않은 좁은 틈·반사 경로, 최대 반사 횟수,
실물과 CAD의 틈·재질·광원 차이가 남는다. 해상도/반복/각도 조건을 조절해 재검사한다.


## 역추적 CPU/GPU 비교 검증

Source는 `run_web_gpu.bat`으로 준비한 환경에서 다음을 실행한다. 설치·서버 재시작·
시스템 변경은 하지 않는다. GPU ZIP의 source 환경을 대신 준비해 주는 명령은 아니다.

```powershell
.\.venv-gpu\Scripts\python.exe scripts\verify_observer_gpu_accuracy.py --json-out artifacts\observer-gpu-report.json
```

- production FP64 Ray/BVH preflight의 6개 필수 조건을 모두 확인한다.
- CPU scalar 기준과 CPU batch 첫 실행+warm 2회, GPU batch 첫 실행+warm 2회를 같은
  프로세스와 같은 장면에서 순차 실행한다. 역추적이 사용하는 실제 CUDA 성공 수를 요구한다.
- 정면·45°·85°·89.9°·상하 극각·복합각·CAD Face·얇은 광원·0.4 mm 틈·정반사 1/2회·
  확산·BSDF·차폐·ALLOWED·광원 뒷면·BSDF 반사율 0의 17개 합성 장면을 검사한다.
- 모든 각도/셀의 수·반사 횟수·제외 수·위치와 설정을 비교한다. 정수는 exact,
  실수는 상대 1e-9/절대 1e-12이다. 양성 장면은 30개 이상의 해당 경로를 요구하고,
  음성 장면은 0개를 요구한다. 허용 홀은 제외 수 30 이상 및 남은 검출 0개를 요구한다.
- preflight 실패 시 GPU 실행을 시작하지 않는다. CPU 검증 결과와 GPU 미검증을 구분하고
  전체 `passed=false`, 종료 코드 2를 반환한다. CPU fallback의 결과가 같아도 GPU 통과가 아니다.
- `--cpu-only`는 CPU 검사만 수행한다. 이때도 GPU 검증의 전체 통과로 보고하지 않는다.
- JSON은 baseline commit, 실제 입력 코드 SHA-256, 조건·경로 수·오차·각 실행 시간·
  CUDA 성공/시도·CPU fallback 정보와 실패 원인을 포함한다.
- 시간 범위는 BVH 준비 이후의 역추적 전체(공통 CPU 처리 포함)이다. CAD import, BVH 구축,
  광원 추적 및 UI 전체의 속도 비교가 아니다. 실물 정확성 검증도 별도다.


## 후보 삭제와 표시 제어

- Leak Candidates 각 항목의 휴지통은 현재 후보와 그 후보에 속한 강조점만 제거한다.
  겹치는 ROI 경계만으로 점을 지우지 않으며, 다른 후보·각도별 집계·해석 원본과 이미
  생성한 ROI/Receiver는 유지한다. 재실행하면 새 결과에서 다시 나타날 수 있다.
- Block 그룹의 체크박스와 ON/OFF는 해석 적용이다. 개별 눈 아이콘과 Hide All/Show All은
  화면 표시만 바꾼다. `ON + Hide` 상태로 숨긴 채 해석에 적용할 수 있다. 표시 변경만으로
  기존 Preview 결과나 해석 입력을 무효화하지 않는다.
- Ray Tracing > Emitter의 눈 아이콘은 해당 광원의 면·윤곽·방향 화살표·Aim 분포를 함께
  숨기거나 표시한다. LED Array는 묶음 또는 개별 표시를 바꾸고 Hide All/Show All도 사용할
  수 있다. 체크박스 enabled는 계속 해석 적용이다. Hide는 광원 수·출력·분포와 진행 중
  작업, 결과 및 Batch 설정 동일성을 바꾸지 않는다. 표시 상태는 Workspace/Case에 저장한다.
- ROI 미리보기에서는 Datum/Reference Plane, Face/Body Emitter와 Aim 분포·화살표도
  활성 ROI 합집합으로 표시를 자른다. 기존 Section 절단을 추가로 유지한다. 화면용 shader
  절단이며 저장된 Emitter 원본을 수정하지 않는다. ROI를 해제하면 전체 표시로 복귀한다.
  실제 해석의 발광·검출 범위는 아래 ROI 계약으로 별도 제한한다.


## ROI의 실제 발광·검출 제한

ROI 미리보기의 표시 CUT과 별개로, Ray Tracing 요청에 `analysis_roi`를 전달한다.
관찰 ROI가 외부 CAD를 보존하더라도 발광면 전체를 보존하지 않는다.

- Face/Body 발광면은 변환된 실제 좌표에서 ROI 내부 면적으로 제한한다.
- Datum/Reference Plane 및 polygon 광원도 ROI 교집합만 실제 sampling한다. 원본 평면을
  숨기거나 결과를 나중에 거르는 방식이 아니다. ROI 밖 광원은 추적 입력에서 제외한다.
- 관찰 ROI의 발광 sampling patch는 광선을 막지 않는 면으로 별도 준비한다. 전체 CAD의
  차폐·반사 형상은 유지한다. 일반 ROI는 기존 CAD 절단 정책을 유지한다.
- 총광량(total) 설정은 잘린 면적/원래 면적 비율로 해석 광량을 조정하여 원래의 면적당
  출력을 유지한다. nit 및 lm/m² 설정은 값을 유지하고 잘린 면적에서 실제 총광량을 계산한다.
  저장된 광원 사양 자체는 변경하지 않는다.
- 좌표 박스 ROI는 Receiver 평면에 법선 방향으로 투영한 범위에서만 검출한다. Receiver가
  모델 외부로 offset되어 있어도 이 범위에 포함되면 유효하다. 실제 hit마다 binning과 경로
  종료 전에 검사하므로 ROI 밖 Receiver hit가 이후의 유효 경로를 가로채지 않는다.
- 여러 ROI의 합집합을 사용하고 겹친 영역을 중복 발광시키지 않는다. 분리된 영역 사이를
  연결한 가상 발광면도 만들지 않는다.
- ROI 안의 발광면이 없거나 좌표 박스가 잘못되면 전체 광원으로 돌아가지 않고 오류를 낸다.
  Datum/Reference Plane의 해석 ROI 제한에는 좌표 박스가 필요하다.
- 결과 `_roi_scope_summary`에 `roi_source_detection_v1`, 원래/잘린 발광 면적, 면적 비율,
  검출 박스 및 외부 형상 유지 여부를 기록한다. 이 정보 없는 이전 서버 결과에는 UI 경고를 표시한다.
- ROI의 Receiver 판정은 공통 host transport에서 수행한다. GPU 선택 시 CAD 교차 판정은
  기존 CUDA batch를 사용할 수 있으나, ROI를 지원하지 않는 rectangle-only fused transport는
  사용하지 않는다. 실제 CUDA 실행과 속도는 결과와 해당 PC 검증으로 확인해야 한다.

`tests/test_roi_emission_detection.py`는 실제 ROI 밖 광원→거울→Receiver 경로가 원래는
검출되고 ROI 적용 후에는 0건이 되는 사례, 발광점 좌표, 광량/밀도 보존, Face/virtual/polygon,
다중 ROI, Receiver acceptance와 준비 geometry cache를 검사한다. 실제 원격 TV 장면의
재현 및 GPU 하드웨어 검증은 이 합성 CPU 검사와 별도다.


## 통합 Blocker

Preview의 차광 입력은 `홀 막기`와 `Block 만들기`로 구분한다. 전자는 드래그
사각형에 내접하는 48분할 원형/타원형 마개, 후자는 직육면체이다. 홀의 CAD
윤곽 자동 인식 기능은 아니다. 두 형상 모두 완전 흡수체로 실제 전파 경로를
차단하며 Preview와 정밀해석에서 같은 형상을 사용한다. 정밀해석 적용은
Run Options의 Blocker 스위치를 따른다.

드래그를 반복하면 같은 그룹에 독립 영역을 추가한다. `선택 완료` 후에도
그룹의 + 버튼으로 계속 추가한다. 그룹 기본명은 Block 1, Block 2 순서이며
변경할 수 있다. 그룹 ON/OFF와 표시를 따로 관리하고 개별 영역의 위치,
폭·높이·깊이·Offset 및 Reverse를 편집하거나 영역만 삭제할 수 있다.

배치는 드래그 모서리와 주변 CAD 표면을 참조한다. 주변 표면을 찾지 못하면
그룹의 기준 평면을 사용하므로 위치를 확인해야 한다. 내부 부품/홀은 보이는
평면 방향에서 배치한 뒤 Z 또는 Offset을 조정한다.

기존 Allowed Area는 원래 범위와 적용/표시 상태를 보존한 사각 Block 그룹으로
변환한다. 새 UI에서는 별도의 평가 제외 영역을 만들지 않는다. 옛 프로젝트의
필드와 API 입력 파서는 호환성을 위해 유지한다.


## 역추적 검사 수준 자동 배분

새 프로젝트는 검사 수준 `기본`을 사용한다. `빠르게 / 기본 / 세밀하게`는
각도 조합과 광원 수에 맞춰 해상도와 셀 반복을 배분하는 계산량 프리셋이다.
정확도 보장이나 예상 실행 시간의 보장은 아니다. 기준 해상도는 32/64/128,
선호 반복은 1/2/2, 표본 예산은 100,000/300,000/480,000이다. 예산이 부족하면
추가 반복보다 공간 해상도를 우선하며, 반복을 1로 줄인 후 필요하면 해상도를
낮춘다. 각도 조합 121개와 전체 표본 500,000개 제한은 유지한다.

각도·주변 범위·간격은 자동 변경하지 않는다. 각도 수 자체가 초과하면 실행 전
경고와 `간격 자동 조정` 버튼을 표시하고 실행을 막는다. 이 버튼을 누를 때만
주변 범위에 맞춘 간격을 적용한다. 실제 전송할 해상도/반복은 고급 설정에서
확인할 수 있다. 고급 설정의 `직접 설정`을 켜면 수동 입력하며 기존 한도도
계속 적용한다. sampling 필드가 없는 옛 프로젝트는 수동값을 보존한다.

UI 계산량 예산은 광원 투영 보완 표본과 서버의 보수적인 2배 표본 제한을
함께 반영한다. 전송하는 observer_probe에는 UI 프리셋 이름을 포함하지 않고
실제로 계산된 resolution/samples_per_cell만 담는다. 반사 경로 및 차폐 검사의
추가 교차 계산 비용은 이 표본 수에 포함되지 않는다.


## ROI 안의 Preview 발광점 표시

ROI List의 각 좌표 박스는 `수정`에서 시작·끝 좌표를 입력한 뒤 `적용`할 수 있다.
기존 ROI의 ID·이름·활성 상태·관찰 각도는 유지하고, 변경된 범위에 포함되는 CAD 면을
현재 부품 변환 좌표로 다시 계산한다. Viewer의 ROI와 Preview Leak 표시도 같은 범위를 따른다.
평면 ROI의 깊이 방향은 편집하지 않으며 Preview 자동 ROI의 Z ±∞ 설정도 유지한다.
잘못된 값이나 CAD 면이 없는 범위는 오류를 표시하고 기존 ROI를 유지한다.
`취소` 또는 Case 전환은 미적용 좌표를 버린다.

활성 좌표 박스 ROI가 있으면 Preview Leak의 halo/core 점을 활성 ROI 합집합
안에서만 표시한다. 비활성 ROI는 표시 범위를 늘리지 않는다. ROI를 모두
비활성화하거나 삭제하면 원본 검출 포인트를 다시 표시한다. 이는 표시 필터이며
검출 결과·각도 집계·후보 목록을 삭제하거나 재계산하지 않는다.

Preview 자동 생성 ROI의 zUnbounded=true는 Z 양방향 제한 해제를 뜻하며
ROI 목록에 Z ±∞로 표시한다. 표시용 Z 좌표와 관계없이 점·광원 표시에서 Z로
자르지 않는다. 해석 요청의 z_unbounded=true는 현재 CAD, 발광면 및 Receiver의
모든 깊이를 포함하는 유한 내부 범위로 환산해 수치 계산한다. 수동 XYZ ROI는
사용자가 입력한 Z 범위를 유지한다.


## Receiver 시야각 배치와 각도별 정밀해석

Ray Tracing의 Receiver > 시야각에서 기준 축, 좌우/상하 각도, 주변 범위와
간격을 직접 지정할 수 있다. Preview 계산 없이 실행 가능하며 Preview 각도
가져오기는 입력한 각도 조건만 복사한다. 후면 -Z에서 좌우 +는 +X, 상하 +는
+Y이고 observer_probe의 방위각/고도각 규칙과 같다.

Receiver는 관찰 기준점을 관찰 방향으로 투영하고, 변환된 전체 CAD 경계의
가장 바깥 지점보다 외부 여유(mm)만큼 밖에 배치한다. Width/Height, Grid,
Acceptance Angle은 각각 독립적으로 유지한다. 유한 사각 수광면의 측정이며
평행 관찰 역추적의 경로 수를 밝기로 변환하는 기능은 아니다.

주변 범위가 0이면 단일 Receiver로 일반 정밀해석을 한다. 범위가 있으면 중심,
끝점, 간격의 좌우×상하 조합을 만들고 최대 121개로 제한한다. 여러 각도의
Receiver를 동시에 계산하지 않는다. 각도별 해석에서는 시야각 Receiver 한
개만 활성화해야 하며, 원본 Case와 Receiver를 바꾸지 않는 실행용 snapshot을
만들어 기존 Batch 제어기로 하나씩 실행한다. 자동 수렴도 각도마다 독립 적용한다.
원본 설정이 바뀌면 이후 실행을 시작하지 않는다. 중단 시 현재 backend job의
종료를 확인한 뒤 나머지 각도를 취소한다.

시야각별 정밀해석 창은 Ray Tracing 패널을 접어도 유지되며 닫기만 해서는
실행을 중단하지 않는다. 완료한 각도별 Flux/Hit 및 기존 결과 창에서 각도의
Heatmap·경로를 비교하고 결과 파일로 저장할 수 있다. 각도별 결과는 원본 Case
결과를 덮어쓰지 않는 별도 결과 모음이므로 결과 창에서 저장한다.

실행 전 표시하는 기본 총 Ray = 활성 광원의 Ray 합 × 각도 수이다. 자동 수렴을
사용하면 최대 배수에 따라 실제 Ray 수가 더 커질 수 있다. 이 기능이 기존
5천만 Ray·반사 50회의 단일 해석을 빠르게 해주는 것은 아니다.

view_angles는 UI 배치/스윕 설정으로 프로젝트에 보존하고 서버 요청에서는
제거한다. backend에는 해석할 단일 Receiver의 center/normal/u_axis/v_axis를
전송한다. 시야각 Receiver와 활성 ROI를 함께 쓰면 ROI 밖 차폐·반사 형상은
보존하고 발광/검출 범위 제한은 기존 analysis_roi 계약을 따른다. 일반 Case
Batch나 직접 요청 생성기로 범위가 있는 template을 한 번만 실행하려 하면
명시적으로 실패하여 중심 각도 결과를 전체 스윕 결과처럼 저장하지 않는다.
