# PERF 5C 정밀 히트맵 최적화와 CAD 탐색 후보 검증

후속 커널 후보와 GPU 재검산 분기 계측은
[`커널 후보와 재검산 병목`](2026-10-19_perf5c-kernel-replay-bottleneck.md)를 따른다.
아래 수치는 이 보고서 작성 시점의 고정 기준 결과다.

목표는 고정 기준 `157230c6` 대비 CPU와 GPU 각각 최소 2배, 즉 같은 해석의
반복 실행 시간을 절반 이하로 줄이는 것이다. LT 대비 2배라는 뜻은 아니다.
**GPU 전체 2배 목표는 미완료다.** 이번 기본 GPU 재측정에서 복잡 CAD는
1.309배, 확률 반사 부하는 1.761배다. 앞선 세션에서 확률 반사가 2배를
넘었어도 안정적인 목표 달성으로 보지 않는다.

현재 CPU 자동 정책은 대표 7조건에서 2.111~4.882배다. 이번에 CPU 수송 코드를
다시 바꾼 것은 아니며, 앞서 반영한 PERF 5B 구현의 최신 작업본 재검증이다.

이번에는 정밀 히트맵 진단 경로를 개선했다. 갇힌 구조의 순서 집계는 기존
스캔 방식보다 1.320배 빨라졌지만, 기본 atomic 경로보다 모든 조건에서
빠른 것은 아니다. 따라서 기본 모드와 UI 선택은 바꾸지 않았다.

## 정밀 히트맵 집계 변경

셀마다 들어온 광량의 FP64 비트 최솟값과 최댓값을 정수로 기록한다. 두 비트가
같으면 모든 광선의 광량이 같으므로 hit 수와 기존 누적값으로 정확한 반복
덧셈을 재현한다. 단순히 `광선 수 × 광량`으로 바꾸지 않으며, Flux와 제곱
광량의 서로 다른 기존 누적값도 보존한다. 광량이 다른 셀은 기존 primary
순서 스캔과 exact fold로 처리한다.

정수 metadata를 포함한 workspace는 tile 폭을 조절해 64 MiB 이하로 제한한다.
이번 실제 비교의 최대 추가 workspace는 3,328,000 bytes다. 수광이 없는
batch는 할당과 집계를 생략한다. 광선 샘플, 반사율, 반사 횟수, 교차 판정과
출력 셀 크기는 바꾸지 않았다.

비교 대상 `ordered_scan`은 같은 소스에서 새 shortcut을 제거해 재구성한 기존
스캔 대조군이다. 세 모드를 교대 실행한 warm 11회 중앙값이며, 방출광 집계는
모두 atomic으로 고정했다. 첫 호출과 모든 raw 시간은 JSON에 별도로 남겼다.

| 조건 | 기존 순서 스캔 | 새 순서 집계 | 기본 atomic | 기존 스캔 대비 |
| --- | ---: | ---: | ---: | ---: |
| 반사 MIS 65,536 Ray | 0.031393초 | 0.032471초 | 0.030272초 | 0.967배 |
| 반사 MIS 1,000,000 Ray | 0.274112초 | 0.266748초 | 0.229157초 | 1.028배 |
| Face 직달 1,000,000 Ray | 0.268147초 | 0.242046초 | 0.194669초 | 1.108배 |
| 확률 반사 1,000,000 Ray | 0.161782초 | 0.166760초 | 0.161614초 | 0.970배 |
| 갇힌 구조 1,000,000 Ray | 0.290510초 | 0.220005초 | 0.215424초 | 1.320배 |
| TV CAD 100,000 Ray | 0.174440초 | 0.169782초 | 0.170515초 | 1.027배 |

갇힌 구조의 시간 감소는 약 24.3%다. 확률 반사와 CAD 대조군은 이번 입력에서
Receiver hit가 없으므로, 두 조건의 시간 차이를 셀 집계 kernel 가속으로
해석하지 않는다. 새 순서 집계는 6조건 중 4조건에서 기본 atomic 대비 시간
회귀 3% 기준을 넘었다. 정확도 통과와 기본 성능 채택은 별도 판정이다.

## 적용하지 않은 CAD 탐색 후보

두 실험 모두 기본 BVH와 삼각형 순서, 면 ID와 RNG를 보존했다. 각 실험의
동일 세션 기본 경로를 기준으로 warm 5회 중앙값을 비교했다.

| 후보 | 해당 세션 기본 | 후보 | 속도비 | 결정 |
| --- | ---: | ---: | ---: | --- |
| 삼각형 외측 후보 조기 제외 | 0.172622초 | 0.182509초 | 0.946배 | 기본 미적용 |
| 방향 우선 광선 재배치 | 0.171975초 | 0.188749초 | 0.911배 | 기본 미적용 |
| 위치 우선 광선 재배치 | 0.171975초 | 0.191234초 | 0.899배 | 기본 미적용 |
| 방향 부호와 위치 재배치 | 0.171975초 | 0.191524초 | 0.898배 | 기본 미적용 |

조기 제외는 삼각형의 명확한 외측 후보만 먼저 버려 역수 계산을 늦추는
실험이다. 경계 부근 3,000개 교차의 면 ID와 거리 비트가 일치했고, 200,000개
좌표에서 기존 판정이 수용한 값을 제거하지 않았다. 실제 GPU CAD 결과도
정합했지만 더 느려 채택하지 않았다.

광선 재배치는 실행 순서만 바꾸고 출력과 RNG는 원래 primary 번호에 기록한다.
stack은 실행 thread 기준으로 유지했다. CPU 정렬과 index 업로드만 약
0.020~0.023초가 필요했고 전체 시간도 증가했다. 원래 순서의 host 집계와
표시 path가 bit-exact인 검사를 통과했지만 기본 실행에는 넣지 않았다.

## 정확도와 안전성

- 통합 304검사 통과: 238.043초. 기존 CPU/GPU, 물성, Aim, 종료 정책과
  실제 1,000회 반사 검사를 포함한다.
- 정밀 모드 40조건 통과: seed 7169~7173, 8,192/65,536 Ray, 각 4회.
  이산 exact, absolute/relative `1e-12`, 최대 32 ULP 기준을 유지했다.
- 전체 최대 차이는 2 ULP이고 Receiver 기여도는 40조건 모두 CPU와 bit-exact다.
  셀 제곱 광량은 GPU 원래 packet 순서 oracle 대비 최대 0 ULP, 셀 Flux의
  CPU 대비 차이는 최대 1 ULP다. 전체 CPU/GPU 결과 bit-exact를 뜻하지 않는다.
- 이 정밀 검사는 `emitted=ordered`, `grid=ordered`다. 기본 atomic 경로의
  미세한 비결정성이 해결됐다는 의미가 아니다.
- 기본 atomic, 기존 스캔과 새 순서 집계의 공개 결과 정합을 별도로 확인했다.
  새 순서 집계 히트맵은 성능 비교의 각 12회 실행에서 같은 hash였다.
- 추가 검사에는 비영 누적값, 서로 다른 Receiver, 부분 chunk, workspace
  재사용, 최소 subnormal, 부호 있는 0과 오류 후 중복 없는 CPU 복구가 있다.
- 실제 장치 memcheck 3검사, 24.816초, 오류 0건이다. synccheck 1검사,
  5.789초, 오류 0건이다. Python 구문 검사와 diff 공백 검사도 통과했다.

## 고정 기준 CPU 재측정

기준 CPU 4 worker와 현재 자동 수송 정책의 최대 8 worker를 같은 세션에서
교대 실행했다. batch는 수동 고정하지 않아 높은 반사 상한에서도 실제 기록량에
따라 조정한다. warm 3회 중앙값이며 모든 공개 결과의 semantic hash가 기준과
bit-exact이고 교차 및 reducer fallback은 0이다.

| 조건 | Ray 수 | 기존 CPU | 현재 CPU 자동 | 속도비 |
| --- | ---: | ---: | ---: | ---: |
| Face 직달 | 1,000,000 | 1.411951초 | 0.418138초 | 3.377배 |
| 확률 반사 | 1,000,000 | 1.509993초 | 0.549493초 | 2.748배 |
| 갇힌 구조 상한 10 | 1,000,000 | 9.193514초 | 4.355597초 | 2.111배 |
| TV CAD 부하 | 100,000 | 1.670684초 | 0.741542초 | 2.253배 |
| 첫 면 흡광 상한 20 | 100,000 | 0.144690초 | 0.056420초 | 2.565배 |
| 첫 면 흡광 상한 100 | 100,000 | 0.134911초 | 0.062184초 | 2.170배 |
| 첫 면 흡광 상한 1,000 | 100,000 | 0.301820초 | 0.061822초 | 4.882배 |

첫 Face 호출은 14.517856초, 새 기록 형식이 처음 필요한 흡광 상한 20의 첫
호출은 13.174124초였다. cold JIT까지 2배 빨라졌다고 주장하지 않는다.
CPU와 GPU 표의 속도비는 각자의 이전 구현 대비이며 CPU/GPU 직접 비교가 아니다.

### 수동 batch 설정의 별도 비용

첫 재측정에서 benchmark 인수로 batch 32,768을 강제했을 때는 CPU 자동 batch
증가 정책이 꺼졌다. 상한 1,000에서 깊이 기준 보수적 크기 2,048을 유지해
49 chunk, warm 0.258765초, 기준 대비 1.174배였다. 이 결과도 삭제하지 않았다.
수동 인수를 빼고 제품의 자동 정책으로 실행하면 5 chunk, 0.061822초다.

이는 같은 자동 설정을 반복한 성능 회귀가 아니라 명시적인 API batch override와
기본 자동 정책의 차이다. 재측정 과정에서 이 설정을 제품 코드 오류로 간주해
고치거나 수동 override 계약을 바꾸지 않았다. 원본 artifact 둘을 함께 보관한다.

## 고정 기준 GPU 재측정

기준과 후보를 같은 프로세스에서 교대 실행한 warm 3회 중앙값이다. 기본
atomic 설정을 그대로 사용했으며 정밀 진단 모드의 추가 속도비를 곱하지 않았다.

| 조건 | Ray 수 | 기존 GPU | 현재 GPU | 속도비 |
| --- | ---: | ---: | ---: | ---: |
| Face 직달 | 1,000,000 | 0.588495초 | 0.196161초 | 3.000배 |
| 확률 반사 | 1,000,000 | 0.450886초 | 0.256090초 | 1.761배 |
| 갇힌 구조 상한 10 | 1,000,000 | 0.466974초 | 0.226341초 | 2.063배 |
| TV CAD 부하 | 100,000 | 0.233100초 | 0.178138초 | 1.309배 |
| 첫 면 흡광 상한 20 | 100,000 | 0.047810초 | 0.029043초 | 1.646배 |
| 첫 면 흡광 상한 100 | 100,000 | 0.094795초 | 0.027713초 | 3.421배 |
| 첫 면 흡광 상한 1,000 | 100,000 | 0.448060초 | 0.030154초 | 14.859배 |

Face 후보 첫 호출은 6.919200초로 JIT 비용을 포함한다. 이후 조건의 첫 호출은
같은 프로세스의 이미 준비된 kernel을 쓴다. 높은 상한의 흡광 대조군은 첫
면에서 종료되므로 실제 1,000회 반사를 14.859배 가속했다는 뜻이 아니다.
CAD import와 BVH 사전 준비 시간도 위 ray-tracing 시간과 별도다.

## 장치와 실행 증거

Source checkout `main@157230c68dabaf5dca1f82b1767793f9ef835a0a`의 로컬 작업본,
Python 3.13 x64, Numba 0.66.0, NVIDIA GeForce RTX 3070, driver 591.59,
CUDA Toolkit 13.1 환경이다. source hash를 각 결과 파일에 고정했다.

```text
available=true
strict_float64=true
kernel_executed=true
kernel_verified=true
preflight_scope=production_ray_bvh
provider_contract=strict_float64_bvh_v1
```

선택은 `compute_backend=gpu_cuda`와 BVH다. 정상 성능 검사는 모두
`compute_execution_state=gpu_active`, CUDA 성공/시도 일치, CPU hybrid와
resident fallback 0, fallback reason 없음이다. 고정 기준 GPU 표의 앞
3조건은 CUDA 16/16, 나머지는 2/2다. 정밀 40조건은 각각 1/1이다.
Face와 Datum Plane emitter를 사용했다. 의도적인 오류 주입에 따른 CPU
복구 검사는 정상 GPU 성능 수치에 섞지 않았다.

## 남은 작업

GPU의 복잡 CAD 탐색과 작은 흡광 대조군이 2배 목표에 못 미친다. 정밀 집계도
가변 광량의 읽기 비용을 더 줄여야 기본 적용을 검토할 수 있다. 큰 batch나
새 BVH를 일괄 적용하지 않고, 면 ID와 미소 간격 검증을 유지하며 비교한다.
LT 정합과 1억 Ray의 절대 시간 검증은 이번 측정에 포함하지 않았다.

UI 변경, 환경 설치, 서버 재시작, 커밋과 push는 하지 않았다.
