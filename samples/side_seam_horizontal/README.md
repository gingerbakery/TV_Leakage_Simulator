# TV 오른쪽 측면 하단 가로 이음매

사내 도면을 사용하지 않고 만든 축소 개발용 STEP입니다. 앞선 세로 이음매 샘플과 달리, 오른쪽 측면에서 가로로 보이는 깊이 방향 이음매입니다.

## 구조

- 전면 +Z, 오른쪽 측면 +X, 위쪽 +Y입니다.
- 내부 크기120 × 80 × 16 mm, 외피 두께0.4 mm입니다.
- 오른쪽 외피 x=120.4 mm에서, 고정된 하단 높이 y=8 mm를 따라 깊이 z=2~14 mm의 12 mm 구간에 가로 틈을 만들었습니다.
- 데코는 이음매 위쪽, 샤시는 아래쪽입니다. 실제 틈의 높이는 y=8~8+gap mm이며, 나머지는 모두 불투명한 밀폐 계입니다.
- 갭0.1/0.3/0.5 mm의 개구 면적은1.2/3.6/6 mm²입니다.
- 광원은 기존 샘플과 동일한104 × 64 mm 램버시안 면광원, 중심[60,40,11.5] mm, 방향+Z입니다. 물성도 반사율0.2인 동일한 임의 무광 조건입니다.
- 전체 모델을 해석하며 ROI·부품 제외를 사용하지 않습니다.

## 밝기 비교 프리셋

0.3 mm의 같은 가로 틈을 대상으로 실제 광원 출력을 바꿉니다. 모든 조건은CPU500,000 rays, seed20260907, 최대반사깊이4, 경로저장5,000으로 동일합니다.

| 프리셋 | 실제 광원 출력 | 의미 |
|---|---:|---|
| horizontal_gap_0p3_off | 0 lm | 광원 끔 |
| horizontal_gap_0p3_1x | 1 lm | 기준 광원 |
| horizontal_gap_0p3_4x | 4 lm | 기준의4배 광원 |
| horizontal_gap_0p3_16x | 16 lm | 기준의16배 광원 |

추가로 horizontal_gap_0p1_1x와 horizontal_gap_0p5_1x는 각각0.1/0.5 mm 갭을 동일한1 lm 광원으로 비교합니다.

0 lm 프리셋도 실제CPU해석입니다. 에너지가0인 기하학적 광선이 수광기에 도달할 수 있으므로, 수광 경로 수가0이 아니어도 광속과 렌더링은0입니다. 결과를 임의로 만들어 넣지 않았습니다.

밝기 비교에서 화면의 자동 노출을 바꾸는 대신 실제 해석 광원의 출력만 바꿨습니다. 1:4:16은 선형 광량의 비율이며 표시 변환 뒤 화면 픽셀값이나 인간의 지각 밝기가 정확히 그 비율이라는 뜻은 아닙니다. nit와 시인 한계는 아직 보정하지 않았습니다.

## 열기

1. 원하는 이름의 BITSAM을 불러옵니다.
2. 같은 이름의 STEP을 연결합니다.
3. 미리 저장된 조건으로Ray Tracing을 실행합니다.
4. 결과의3D 빛샘 보기에서 오른쪽 측면을 선택합니다. 깊이 방향 선이 가로로 보입니다.

BITSAM은 설정 전용입니다. 새Case와 결과가 정확히 연결되도록 실제Run을 한 번 실행해야 합니다. 렌더링에서 추가 광학 조건 설정은 필요하지 않습니다.

## 재현

대용량 `*.result.json`은 Git에 포함하지 않습니다. STEP/BITSAM으로 새 해석을 실행하는 시연에는 필요하지 않습니다. 저장 결과 파일을 읽는 검증 스크립트를 실행하려면 저장소 의존성이 준비된 Python으로 아래 생성기를 먼저 실행합니다. 같은 이름의 합성 생성 자료를 갱신하므로 별도로 수정한 샘플은 먼저 다른 위치에 보관합니다.

```powershell
python scripts/generate_horizontal_seam_samples.py
```

저장소 의존성을 준비한 뒤 자동 시연용 파일을 배치하려면 저장소 루트에서 다음을 실행합니다. 출력 폴더는 자동으로 생성됩니다.

```powershell
node scripts/stage_horizontal_seam_demo.mjs
```

로컬 앱을 실행하고 `/?demo=horizontal-seam` 주소를 열면 16 lm 프리셋으로 실제 CPU 해석을 수행한 뒤 3D 빛샘 보기로 진입합니다. 현재 시연 서버의 주소는 `http://127.0.0.1:8788/?demo=horizontal-seam`이며, 다른 포트로 실행했다면 해당 포트를 사용합니다.

- scripts/generate_horizontal_seam_samples.py: STEP,요청,실제CPU결과,교차점,validation.json 생성
- scripts/horizontal_seam_project_helper.mjs: 설정 전용BITSAM 생성
- validation.json: 모든 저장 수광 경로가 실제 가로 틈을 통과하는지, 전체 수광 경로가 저장됐는지, 실제 광원 출력에 선형으로 응답하는지 검증

## 실제 CPU 기준 결과

| 갭 | 광원(lm) | 수광 경로 수 | 수광 광속(lm) |
|---|---:|---:|---:|
| 0.3 mm | 0 | 104 | 0.00000000e+0 |
| 0.3 mm | 1 | 104 | 8.10201218e-6 |
| 0.3 mm | 4 | 104 | 3.24080487e-5 |
| 0.3 mm | 16 | 104 | 1.29632195e-4 |
| 0.1 mm | 1 | 10 | 3.50876865e-7 |
| 0.5 mm | 1 | 202 | 1.54102549e-5 |

각각의 모든 수광 경로를 저장하고, 모두 실제 가로 틈을 통과하는지 검사했습니다. 0.3 mm 동일 형상에서1/4/16 lm은 같은104개 기하학 경로를 만들며 수광 광량은 정확히1:4:16입니다. 광원0 lm에서도 같은 기하학 경로104개가 기록되지만, 경로의 입사 에너지와 수광 광속은 모두0입니다. 0.1 mm 조건은 표본10개이므로 국부 밝기 수렴을 주장하지 않습니다.
